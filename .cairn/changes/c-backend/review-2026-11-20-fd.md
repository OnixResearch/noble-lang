### 4. Input integrity (`inputs.rs`)

- **Path parsing (`:23-59`).**
  - A leading `/` is required.
  - Every component must be non-empty, so `//`, a trailing `/` and a bare `/`
    refuse.
  - `.` and `..` refuse, and every component must be UTF-8.
  - At most 128 components are allowed: 128 pass, 129 refuse.
  - A non-UTF-8 SOURCE never reaches this code: `options()` refuses it with
    the usage text (`c_backend.rs:556`).
- **Walk (`:80-97, :166-177, :238-242`).**
  - `/` is opened with `O_DIRECTORY` and `O_NOFOLLOW`. Then one `openat`
    with `O_NOFOLLOW` runs per single-component name.
  - Every ancestor symlink and leaf symlink refuses, and so do magic links
    such as `/proc/self`.
  - Each step is relative to an already-open descriptor, so the walk has no
    TOCTOU window.
- **Leaf checks (`:178-191`).**
  - `fstat` runs on the opened descriptor. The leaf must be a regular file
    with `st_nlink == 1` and size ≤ max.
  - The bounded read refuses an oversized input rather than truncating it.
    Exactly max bytes is accepted.
- **Seal (`:128-159`).** The memfd gets the WRITE, SHRINK, GROW and SEAL seals,
  all four are read back and checked, and the bytes are read back and compared.
  The seal itself adds little; see N-1.
- **Leaf recheck (`:193-204`).** `statat` with `SYMLINK_NOFOLLOW` in the held
  parent compares `(st_dev, st_ino)`. That detects the leaf being renamed over
  or deleted during the snapshot; N-1 lists what it misses.
- **Output (`:208-269`).** The code walks the parent, runs `mkdirat 0755` and
  reopens the directory with `O_DIRECTORY` and `O_NOFOLLOW`. Each child is
  then created through that descriptor with `O_CREAT`, `O_EXCL` and
  `O_NOFOLLOW`. The identity check has the gap in F-7.
- **Messages.** Each refusal class has its own message. A few misattribute;
  see N-2.
- **Safety and binding.**
  - There is no `unsafe`, no Cargo manifest change and no feature change.
    `rustix` already enables `fs`.
  - All three inputs use `inputs::snapshot` (`c_backend.rs:1239-1241`) and
    the outputs use `inputs::create_output` (`:1281`).
  - `INPUTS_SOURCE` (`:29`) is hashed into the build subject (`:1256`) and
    recorded in the manifest as `input_integrity_source_sha256` (`:1270`).
- **Base behaviour (`6aa08447`).**
  - `read_bounded` opened the whole path with `O_NOFOLLOW` on the final
    component only (`c_backend.rs:508-528`). Ancestor symlinks, relative
    paths, `.`/`..` and hard links were all accepted.
  - The base wrote outputs with `create_dir`, then re-resolved
    `options.out.join(name)` for each file (`:1265-1284`).

### 5. Emitter slice

- **Encoding.** The Pair/Sum/List wrappers match
  `worker_program_transition.rs:345-380`, and the I64/Bool/Text leaves match
  `:332-339`. Unit does not match (F-1).
- **Gating.**
  - The static gate (`controls`, `result_text`) is complete.
  - At runtime, `emit_value` fails `invalid output tag` for `TAG_PROGRAM`, and
    the runtime has no Syntax tag at all.
  - The output guard (`:1215`) requires height 1 and the exact checked result
    shape.
  - A Program or Syntax value therefore cannot reach the output.
- **Depth and quota.**
  - The depth bound is sound but unreachable (N-4).
  - `append_bytes` and `append_byte` fail `output bytes exhausted` before
    overflow (`:72, :79`).
  - The List loop terminates because tail indices strictly decrease
    (`:140`), and the quota bounds it as well.

  - CB-BUILD-01 `spec.md:67-69` ("one I64/Bool/Unit/Text result") and `:90-91`
    ("Final Pair/Sum/List/Syntax/Program results … still refuse"). These stay
    contradicted until a correctly dated paragraph is synced (F-2, F-4).
  - CB-ADMIT-01 `spec.md:353-359` (F-3).

### 6. Tests

- **Tests 1-3 fail on the base.** The base accepts `/./`
  (`relative_dotdot_…`), an ancestor symlink and a hard link
  (`symlinked_and_hard_linked_…`), and an output under a symlinked parent

  path, `..`, a trailing `/`, a leaf symlink, an existing output and a
  symlinked output leaf. Those cases fail on the base only because the
  diagnostic text differs.
- **Test 4 is not an integrity test.** `emitted_inputs_…` checks the byte copy
  and determinism. It fails on the base only because `Pair<I64,Bool>` was
  refused there.
- **The emitter tests are meaningful but syntax-only.** The C11 cases

  of nested `Program` and `Syntax` (`:439-442`) and the aggregate test
  (`:652-706`) bind results to the exact checked interface.
