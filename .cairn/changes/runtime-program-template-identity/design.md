## Context

P-ID-01 names a resolved definition by its semantic body/dependencies; P-ID-03 distinguishes captured program values, and ID-05 expects one template across capture 2→3. P-RECIPE-03 normalizes composition without flattening quotation, while P-RECIPE-04 deliberately retains the actual captured literal in the inert recipe. These establish equality relations, not a way to authenticate a new target `DefinitionId` for an anonymous returned program. Existing VC-LSLOT-01/EV-LSLOT-01 require the selected target P/D, captures and artifact; the builder definition and its family theorem do not supply that D. `P-ID-01` r[P-ID-03] `P-RECIPE-03` `P-RECIPE-04` `VC-LSLOT-01` `EV-LSLOT-01`

## Decisions

### Decision: Independently checked anonymous template, not builder identity

**Choice:** This *draft* proposes an anonymous definition-template identity domain distinct from named definitions. Only a closed returned `Program` at an identity-bearing admission boundary receives a target D: first reify its actual immutable VM value, independently check its typed finite graph and resolved dependencies, then normalize an identity projection with typed runtime-capture slots. The source/guest builder `quote [ + ] compose` has its own definition identity and may only establish checked origin; its D, a generic caller D, a slot label or a manifest-supplied string is never the returned target D. An ordinary runtime `quote`/`compose` or `run` need not eagerly create an ID, compile source or invoke a prover. r[P-ID-03] `P-ID-04`

**Rationale:** P-RECIPE-04's exact reflected `quote(I64(2))` contains literal 2 and `quote(I64(3))` contains literal 3. Identifying a common template requires an independently authenticated distinction between a runtime-origin capture and a *fixed source literal*, not replacement of every literal by a hole. Preserve the exact literal-bearing recipe for reflection/P and separately project the D skeleton: canonical ordered typed capture slots by normalized first occurrence, repeated-slot aliasing, resolved quotation/compose shape, instantiations, effects, dependencies and self-owner scope. The captured payload changes P but not that D; changing a fixed literal, slot shape/aliasing, owner or semantic dependency changes D. Source formatting, VM addresses and optimizer grouping remain irrelevant. `P-ID-01` r[P-ID-03] `P-RECIPE-03` `P-RECIPE-04`

### Decision: Authenticate reification and preserve claim boundaries

**Choice:** A host selecting a returned target must independently bound/copy its complete immutable VM program/capture graph and check actual captures, ordered interface, effects, resolved references and any recursive owner against the accepted `quote`/`compose` occurrences in the selected context. The producer must establish capture-slot provenance across the compiled VM operations; identical payload bits or a recipe event marked `I64` cannot authenticate their origin. If the host cannot prove that relation, or a slot/alias/owner is ambiguous, identity-bearing admission refuses; plain checked execution stays distinct. Template D plus typed capture values and exact checked recipe/interface form P; the compiler separately binds the exact candidate to the installed Wasm bytes. This amendment does not select an encoding/hash/version under P-ID-04. r[P-ID-03] `P-ID-04` `P-ID-07`

**Rationale:** Today's VM Program cell records capture/compose children and a recipe, but the literal-bearing reflection event cannot by itself distinguish accepted runtime capture from a fixed literal or supply a trustworthy target D. An existing bounded `Live-Wasm-Draft` guest self-edit decoder reifies numerical source for *that separate profile*; its generated named source identity is not an anonymous `Live-Slot-Design` target identity. A forged, truncated or ownerless snapshot must not borrow the builder's D merely because a previous source compilation succeeded. r[P-ID-03] `VC-LSLOT-01`

### Decision: Exact selected target, replay eligibility and proof remain separate

**Choice:** LSLOT-05's P2/D2 and LSLOT-08's Ptrace/Dtrace are symbolic fixture inputs, not actual identities supplied by this draft. A future positive selection requires independently admitted *actual target* P/D with the selected capture, instantiated interface, semantic context, claim, assumptions and installed Wasm correspondence. A frozen-registry replay must also match the slot epoch/incarnation/generation, selected artifact and exact ordered host request/response/accounting; eligible replay is neither behavioral proof nor real-effect authority. A builder-family theorem, generic caller proof, replay transcript or correct template D alone cannot satisfy proof-required admission. `P-ID-06` `P-ID-07` `VC-ID-02` `VC-LSLOT-01` `EV-LSLOT-01`

**Rationale:** The existing contracts already separate identity, applicability, source/artifact correspondence, replay and host authorization. The only missing normative edge proposed here is authenticated construction of the anonymous target's D/P; this change does not duplicate or promote those accepted boundaries. r[P-ID-03] `VC-LSLOT-01` `EV-LSLOT-01`

### Decision: Smallest future source cutover, not part of this draft

**Choice:** Extend the independent Rust acceptance path (`crates/noble-kernel/src/acceptance/`) to validate the selected closed target and origin/owner witness; preserve VM `quote`/`compose` capture provenance alongside `crates/noble-wasm/runtime/programs.wat`, `reflection.wat` and the documented Program cell ABI. Extend `crates/noble-wasm/src/source/admission/identity.rs` and target compilation metadata so *target* D/P/captures bind the installed artifact rather than reuse a source-builder definition identity. The eventual host live-slot admission must authenticate and freeze that selected value before CAS or evidence lookup, not repurpose `crates/noble-cli/src/core/live.rs` guarded self-edit. A strict Lean consumer must bind the newly checked target to actual extracted checker/statement and artifact premises; `proofs/mc1/NobleContractImpl/Statement.lean` currently exports a builder-family source statement, not a source-bound returned-target proof. No source implementation or Lean claim changes in this draft. r[P-ID-03] `V-MODEL-01` `VC-LSLOT-01`

## Risks / Trade-offs

- **Owner-selected normative blocker:** the language owner must independently approve the proposed anonymous D identity domain and authenticated capture-slot projection (rather than weakening ID-05 or calling the builder D the target D), including how compiled VM occurrences securely attest runtime capture origin and scoped owner. Without that choice, identity-bearing admission and positive LSLOT-05/08 remain blocked. P-ID-04 independently leaves canonical encoding and cross-implementation stable IDs open; experimental local IDs do not resolve this provenance choice or establish source-bound proof. r[P-ID-03] `P-ID-04`
- Tracking a trusted provenance witness may require extra bounded metadata; raw reflected literals, digest folds, source spans and guest-writable memory cannot be silently substituted. Existing accepted code, immutable saved Programs and Core/guarded-live boundaries remain unchanged. r[P-ID-03] `P-ID-05`
