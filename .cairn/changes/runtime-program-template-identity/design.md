## Decisions

### Decision: Independently checked anonymous template, not builder identity

**Choice:** The owner approved this *isolated draft's* anonymous definition-template identity policy, distinct from named definitions; it is not yet a synced canonical rule or implemented admission. Only a closed returned `Program` at an identity-bearing admission boundary receives a target D: first reify its actual immutable VM value, independently check its typed finite graph, source-operand origins and resolved dependencies, then normalize an identity projection with fixed operands and only proven varying-input capture slots. The source/guest builder `quote [ + ] compose` has its own definition identity and may only establish checked origin; its D, a generic caller D, a slot label or a manifest-supplied string is never the returned target D. An ordinary runtime `quote`/`compose` or `run` need not eagerly create an ID, compile source or invoke a prover. r[P-ID-03] `P-ID-04`

**Rationale:** P-RECIPE-04's exact reflected `quote(I64(2))` contains literal 2 and `quote(I64(3))` contains literal 3. Identifying a common template requires an independently checked distinction between a varying-input capture and a *fixed source literal or computed source constant*, not replacement of every quote operand by a hole. Preserve the exact literal-bearing recipe for reflection/P and separately project the D skeleton: ordered typed slots for proved input lineage, fixed semantic operands for input-independent derivations, normalized quotation/compose shape, instantiations, effects, dependencies and semantic lexical recursive owner scope. Captured payload changes P but not D; changing a fixed operand, logical slot alias, lexical owner or semantic dependency changes D. Source formatting, VM addresses and optimizer grouping remain irrelevant. `P-ID-01` r[P-ID-03] `P-RECIPE-03` `P-RECIPE-04`

### Decision: Source-to-operand flow and compiled-site correspondence

**Choice:** At the identity-bearing boundary an independent checker must verify accepted resolved source-to-operand dataflow for every relevant `quote`/`compose` site, its compiler-lowered site mapping and matching *actual* bounded VM graph/captured operand. `[ 2 quote [ + ] compose ]` and `[ 3 quote [ + ] compose ]` vary a fixed source literal and must yield different D; `[ 1 1 + quote [ + ] compose ]` versus `[ 1 2 + quote [ + ] compose ]` likewise varies an input-independent computed constant. The same checked `[ quote [ + ] compose ]` builder supplied once with root input `I64(2)` and once with `I64(3)` has the same D and different P *only if* the checked binding flows to the actual quote operand. Optimizer folding, VM runtime execution of `+`, equal value bits, a reflection event and a `quote` opcode alone cannot change the classification. If constant evaluation, source-to-operand flow, compiler site identity or the actual operand cannot be verified, refuse identity-bearing admission rather than assuming it is a slot. r[P-ID-03] `P-RECIPE-04`

**Rationale:** Historical runtime WIP `2a9f0fdea94b6d99c4d9161e9f7b0da55584ea5e` supplied bounded, D-neutral `selected_origin` for selected I64 builders, with checked source operands through compiled instruction/table sites to the actual epoch-qualified Program graph and a saved-owner control. The trusted worker rechecks the retained owner/handle and actual graph against source/compiler sites. Unsupported source/graph shapes remain opaque; general logical source-binding aliases and lexical recursive owner, canonical P-ID-04 encoding, and complete target identity-bearing admission remain open. A source span or NodeId can help authenticate a site within the checked source/compiler witness but is not an input to canonical D; no raw guest-supplied site metadata suffices. Ordinary quote/compose execution remains unaffected. r[P-ID-03] `P-ID-05`

### Decision: Semantic owner and logical alias, not runtime topology

**Choice:** A required recursive owner means the resolved lexical/scoped self-binding that gives the returned program its semantic reference context, not a VM code owner, allocated cell, handle, pin or retention root. Normalize this binding (including scoped self-reference) in D; checking the actual snapshot's owner witness against it is mandatory where present. Canonical repeated-slot alias classes follow independently checked source-binding lineage, after recipe normalization, rather than a duplicated pointer or equal payload bits. Reusing `q = quote(x); compose(q,q)` and independently constructing `compose(quote(x),quote(x))` from the *same* immutable input binding `x` has one logical alias class and the same target D/P when the checked normalized recipes agree, even if the physical quote graph and heap sharing differ. With independent root bindings `x` and `y` both holding `I64(2)`, `compose(quote(x),quote(y))` has two logical slots and differs in D/P despite equal literal-bearing recipes; incidental VM cell sharing cannot collapse them. These are schematic binding-lineage vectors, not new Noble `let` syntax or executed cases. r[P-ID-03] `P-ID-01`

**Rationale:** VM ownership governs storage and lifecycle, while lexical ownership governs semantic recursive resolution. Physical graph topology may change under composition grouping, copying or optimizer layout; neither that topology nor source spans/NodeIds establish logical alias equality. Checked binding provenance must carry the equivalence relation, reject ambiguous lineage, and preserve separate names for independent bindings even when they currently hold the same bytes. r[P-ID-03] `P-RECIPE-03`

### Decision: Authenticate reification and preserve claim boundaries

**Choice:** A host selecting a returned target must independently bound/copy its complete immutable VM program/capture graph and check actual operands, ordered interface, effects, resolved references and any lexical recursive owner against the checked source-to-site-to-VM mapping in the selected context. If the independent checker cannot prove that relation, or fixed/variable lineage, site, slot/alias/owner or actual graph is ambiguous, identity-bearing admission refuses; plain checked execution stays distinct.
