## Why

Issue #14 asks for a bounded, opt-in way to lower checked pure Noble computation to a fixed numeric graph, optionally with explicitly trainable parameters. The idea comes from [chenglou/handwired at `4ea7fcb`](https://github.com/chenglou/handwired/tree/4ea7fcb27ebe93acf49b9f29a93e162b975bad46). The profile must not replace ordinary Programs and must not select a GPU backend. Today Noble selects only signed wrapping `I64` arithmetic (K-NUM-01). The kernel type universe has `I64` and `Bool` but no FP32 type. No requirement says how a stack Program becomes a graph, which numeric contract a graph obeys, or how parameter learning stays separate from program identity and evidence. Without these contracts, a prototype could quietly reinterpret `I64` Programs as floats, trust caller assertions as proofs, mistake a training surrogate for a derivative, or change trained parameters in place inside captured Programs. r[NGRAPH-SCOPE-01] r[NGRAPH-F32-01]

## What Changes

- Add the nonselected design profile `NumericGraph-Design`. It has two disjoint sub-profiles: exact `ngraph-i64/0`, which exercises stack-to-graph extraction only, and experimental `ngraph-f32/0`, which carries the differentiable slice. There is no implicit conversion between them and no reinterpretation of `I64`. r[NGRAPH-SCOPE-01]
- Publish the operation and type whitelist and an exact IEEE binary32 reference contract. The contract covers the type and ABI, exact-only literals, conversions, operations, rounding order, the ban on fusion and reassociation, signed zero, NaN, infinities, subnormals, index reads, and bitwise observation equality with a single NaN class. It also lists effect exclusions, finite budgets charged on the unpruned expansion, and named diagnostics. r[NGRAPH-F32-01] r[NGRAPH-EXTRACT-01]
- Specify admission and a deterministic symbolic stack-to-graph extraction over kernel-checked derivations, followed by an independent graph checker. Every range, grid, bit, one-hot, finiteness, shape or index fact must have exactly one checked provenance; this is coordinated with #8. r[NGRAPH-EXTRACT-01] r[NGRAPH-FACT-01]
- Separate the training contract from forward semantics. The contract names derivative policies. Boolean and index paths are refused statically by default. An optimizer produces new immutable parameter snapshots with reproducible provenance and never transfers evidence automatically. r[NGRAPH-DERIV-01] r[NGRAPH-SNAP-01]
- Fix the ownership and backend boundary: scratch versus retained owners, cleanup on failure and cancellation, device buffers as host resources, and a CPU-first measurement before any backend decision. The profile is mapped to kernel admission, source extraction, runtime ownership and open proof-to-artifact obligations. r[NGRAPH-OWN-01] r[NGRAPH-BENCH-01] r[NGRAPH-PROOF-01]
- Write Phase B (the CPU-only feasibility experiment) and Phase C (the measured continuation decision) as concrete plans. The owner approved both on 2026-10-15: `F32` graphs are authored directly in `ngraph-ir/0` (B0(b)), the experiment lives in an isolated crate, the binary32 oracle is `rustc_apfloat`, and `evidence` facts are excluded from Phase B.
