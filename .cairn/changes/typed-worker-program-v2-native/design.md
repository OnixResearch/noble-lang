# Source-bound Worker Program v2 design

## Selection and identity

`worker typed` v1 remains pure and byte-compatible. `worker program` v2 is a separate opt-in host/guest contract; `worker-send.wit` remains MW2's distinct shell boundary. Admission retains the prepared ModuleSession, independently checked exported Program owner, exact instantiated input/output/effect witness, checked dependency closure, capture schema/value frames, and scoped recursive owner. The opaque runtime handle is bound to this retained session and cannot be reconstructed from package text, a hash or an artifact. The normalized identity is a semantic relation over checked recipe, exact typed captures, interface and dependencies; chosen wire bytes and optimizer layout are not identity.

## Builders and export/import

`adapt` checks source effects are included in a selected destination effect ceiling and retains the original recipe and original witness; the adapted value retains the destination witness separately. Heterogeneous list insertion/selection, duplication and composition check instantiated stack/schema equality and compose the declared effect witnesses without source compilation or host requests. All recipe expansion/allocation consumes one invocation meter; a failed operation publishes no program. The request conservatively reserves finite slices for module check, selected invocation check and Wasm compilation, charges decode/graph and serialization work, and reserves explicit fuel bounds for Text reattestation and source/guest execution; no nested stage receives an uncharged fresh allowance. Reflection is inert. Export requires an authenticated host-owned destination-and-capture-specific grant *before* package bytes leave the process. A caller-provided file/JSON flag is not such a grant, so the CLI export route is absent until a host-owned authority ingress exists. The current pure I64→I64 package carries a finite indexed named/composed graph, selected node, source-bound dependency recipes, exact host contract version and checked Text aliases; its graph digest is only a consistency claim, not an authorization signature. Import reconstructs every composition against a fresh checked source closure and compares the whole canonical package; reattestation of installed Text precedes acceptance. No live resource or host implementation is serialized. Other typed captures, scoped self-owner references and arbitrary adapted interface witnesses remain unsupported rather than being accepted by a digest, accepted bit or artifact claim. A semantically equal package may use different artifact bytes; neither proof applicability nor authority transfers on import.

## Bounded execution and observation

The selected guest WIT declares a genuine opaque `resource program`: the host's owned instance-scoped resource-table entry retains the actual checked Program cell/recipe, exact source owner, instantiated stack/effect/schema witness and captured values. Guest-supplied numeric resource indices are never identities: ownership transfer and destruction are mediated by the host table. The selected pure I64→I64 Noble→WIT adapter maps `Ty::Program` to this resource only after source-to-installed-cell correspondence and both sides' interface typechecks; no generic numeric-handle fallback. The guest moves the one owner from host admission to host invocation; `dup`/`drop` of this own-resource-backed Program are rejected during guest lowering, and borrow/clone are not exposed without their separate ownership adapter. The Worker source compiler must emit a separate inert `worker_install` and named Program cell accessor: ordinary `submit` runs the wrapper and cannot prove the named cell was installed. The host compares the installed cell's entry, signatures, recipe depth/leaves and capture fields with independently emitted metadata before issuing the WIT owner. It walks bounded installed recipe/Text cells and matches their literal bytes to checked definition identity and lexical node before portable capture serialization or guest admission. The pure host invokes this cell under both Wasmtime fuel and source runtime step/allocation quotas; matching host resource destruction and store drop retire unconsumed ownership. General task cancellation, recall and effectful host operation observation require additional task-owner integration rather than treating MW2's distinct Send future as this Program owner.

## Unsupported shape and dependency gates

Initial source work can support only finite, resource-free *captures* and checked pure source/data; the dedicated WIT Program resource is a host-owned capability to a checked cell, never serializable captured data. The current selected guest is pure I64→I64; CLI rejects a `test.emit` ceiling or effectful package because no authenticated Worker host effect issuer, checked bound adapter or revocation/expiry contract is connected. Other resource captures, an unverified self owner, unknown effect/version, unsigned arbitrary binaries, arbitrary WIT dynamic signatures and unsupported recursive graph shape must reject explicitly. Selected source and component compiler mappings do not change ordinary Own/Borrow=`Ty::Resource`; a token from a single checked named invocation and strict WIT world shape is necessary. The installed source recipe's ordered atoms, quotation children and lexical Text occurrence must match the independently checked compiler layout, including runtime Text bytes. This correspondence does not confer export authority: destination and capture digest grant must come from a real host-owned issuer before serialization, and import re-installs source to bind Text again. Full WORKER-03/04/09/12 execution requires scoped Wasmtime guest runs, nonempty host effects with real protected request/denial accounting and native task integration; source-only code and Cairn validity are not guest execution evidence.
