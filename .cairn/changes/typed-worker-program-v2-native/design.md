# Source-bound Worker Program v2 design

## Selection and identity

`worker typed` v1 remains pure and byte-compatible. `worker program` v2 is a separate opt-in host/guest contract; `worker-send.wit` remains MW2's distinct shell boundary. Admission retains the prepared ModuleSession, independently checked exported Program owner, exact instantiated input/output/effect witness, checked dependency closure, capture schema/value frames, and scoped recursive owner. The opaque runtime handle is bound to this retained session and cannot be reconstructed from package text, a hash or an artifact. The normalized identity is a semantic relation over checked recipe, exact typed captures, interface and dependencies; chosen wire bytes and optimizer layout are not identity.

## Builders and export/import

`adapt` checks source effects are included in a selected destination effect ceiling and retains the original recipe and original witness; the adapted value retains the destination witness separately. The in-memory builder can widen a checked pure Program to a `test.emit` type witness, but that does not issue a host grant, change its recipe, or make the widened witness executable/exportable. Heterogeneous list insertion/selection, duplication and composition check instantiated stack/schema equality and compose the declared effect witnesses without source compilation or host requests. All recipe expansion/allocation consumes one invocation meter; a failed operation publishes no program. The request conservatively reserves finite slices for module check, each dependency-closure walk (one for a pure root; the closure, owner and interface walks for a host-selected binding), selected invocation check and Wasm compilation, charges decode/graph and serialization work, and reserves explicit fuel bounds for Text reattestation and source/guest execution; no nested stage receives an uncharged fresh allowance, and a walk that runs out reports exhaustion rather than an invalid closure. Reflection is inert. Export requires an authenticated host-owned destination-and-capture-specific grant *before* package bytes leave the process: the grant is compared with the source digest and an in-memory digest of the checked captures before any package is constructed, and a denial is its own outcome, never a source-check failure or a successful no-op. A caller-provided file/JSON flag is not such a grant, so the CLI export route is absent until a host-owned authority ingress exists. The current I64→I64 package (`0.1.0-draft.10`) carries a finite indexed named/composed graph, selected node, source-bound dependency recipes, the pure builtin table bound to the kernel semantic revision, the exact host-selected bound-adapter row (none for a pure Program; one for an embedder-selected `test.emit` or `test.code-export` binding) and `Text`-typed checked aliases; its graph digest is only a consistency claim, not an authorization signature. Import reconstructs every composition against a fresh checked source closure under the same independently selected binding, if any, and compares every field of the canonical package except the claimed capture binding before any Wasm is installed; only then does reattestation of installed Text bind that claim. A contract row that matches the selected binding issues nothing; the CLI selects no binding, so it imports pure packages only. No live resource or host implementation is serialized. Other typed captures, scoped self-owner references and arbitrary adapted interface witnesses remain unsupported rather than being accepted by a digest, accepted bit or artifact claim. A semantically equal package may use different artifact bytes; neither proof applicability nor authority transfers on import.

## Bounded execution and observation

The selected guest WIT declares a genuine opaque `resource program`: the host's owned instance-scoped resource-table entry retains the actual checked Program cell/recipe, exact source owner, instantiated stack/effect/schema witness and captured values. Guest-supplied numeric resource indices are never identities: ownership transfer and destruction are mediated by the host table. The selected pure I64→I64 Noble→WIT adapter maps `Ty::Program` to this resource only after source-to-installed-cell correspondence and both sides' interface typechecks; no generic numeric-handle fallback. The guest moves the one owner from host admission to host invocation; `dup`/`drop` of this own-resource-backed Program are rejected during guest lowering, and borrow/clone are not exposed without their separate ownership adapter. The Worker source compiler must emit a separate inert `worker_install` and named Program cell accessor: ordinary `submit` runs the wrapper and cannot prove the named cell was installed. The host compares the installed cell's entry, signatures, recipe depth/leaves and capture fields with independently emitted metadata before issuing the WIT owner. It walks bounded installed recipe/Text cells and matches their literal bytes to checked definition identity and lexical node before portable capture serialization or guest admission. The pure host invokes this cell under both Wasmtime fuel and source runtime step/allocation quotas; matching host resource destruction and store drop retire unconsumed ownership. General task cancellation, recall and effectful host operation observation require additional task-owner integration rather than treating MW2's distinct Send future as this Program owner.

## Unsupported shape and dependency gates

Initial source work can support only finite, resource-free *captures* and checked pure source/data; the dedicated WIT Program resource is a host-owned capability to a checked cell, never serializable captured data. The CLI-selected guest remains pure I64→I64 and rejects a `test.emit` ceiling or effectful package: a CLI argument or source file cannot issue the host-only policy. The separate host embedder API accepts a selected bound adapter and revocable policy, defaulting to absence/denial without an explicit production host caller. Other resource captures, an unverified self owner, unknown effect/version, unsigned arbitrary binaries, arbitrary WIT dynamic signatures and unsupported recursive graph shape must reject explicitly. Selected source and component compiler mappings do not change ordinary Own/Borrow=`Ty::Resource`; a token from a single checked named invocation and strict WIT world shape is necessary. The installed source recipe's ordered atoms, quotation children and lexical Text occurrence must match the independently checked compiler layout, including runtime Text bytes. This correspondence does not confer export authority: destination and capture digest grant must come from a real host-owned issuer before serialization, and import re-installs source to bind Text again. Full WORKER-03/04/09/12 execution still requires scoped Wasmtime guest runs and native task integration; source-only code and Cairn validity are not guest execution evidence.

## Host-only effect and code-export policy (unissued until selected)

The opt-in Worker host, not a source file, package, command-line JSON, WIT import alone or effect witness, selects a policy subject: exact checked named `DefinitionId`, source SHA-256 and source generation, destination identity and policy epoch. A policy selects the exact `test.emit` bound-adapter identity/version/slot and a finite in-memory synthetic ledger, not an arbitrary blocking user callback. Selecting a policy creates **no allow state**. Only after checked installation can an explicit host issuer bind the exact Program scope, address, capture hash and owner; the opaque per-instance `ResourceTable` owner identifies the Program, while each protected callback separately checks current allowance, revocation, epoch, owner and adapter slot. A fresh independent ModuleSession also starts at generation one; the installed Program scope distinguishes sessions with identical source bytes and generation. Neither widening the latent effect nor importing a package mints host effect authority. No production embedder currently calls the explicit issuer; CLI effectful admission denies and is not a caller-controlled flag.

An installation-local host-generated monotonic identity additionally binds each issued allowance and owned Program cell: the same ProgramStore, source, slot, address, owner and capture in a fresh Wasmtime Store must not reuse an earlier allowance. The execution scope exists before task start or host issuance, records the exact cell before publishing its issue, and retires both that issuance and an undelivered task on normal exit, error or unwind. A retry requires a new explicit issue after the retry's checked installation. Issuance and callback compare the full identity under the policy lock; neither guest work nor task retirement holds that lock, and a poisoned lock denies rather than retaining usable authority.

Two different typed host operations are required. The source-bound `test.emit` callback validates the installed owner, checked adapter slot, issued policy allowance and revocation, running task phase and bounded per-request count/Text size **on every request**, within the pre-reserved guest work and fuel budget. It reserves a finite ledger quota and appends to the host-selected destination atomically under the same lock as revoke and task cancellation, then counts completion; revoke/cancel acknowledgment cannot overtake an in-flight append. Its receipt distinguishes attempted requests, completed protected appends and denied requests without inventing external effect success. A separate declared `test.code-export` effect and WIT `own<program>` request carry a checked Program with private Text and a guest-requested destination; this host **default denies** regardless of destination. The host checks the installed owner/capture and records one redacted denial before constructing/serializing source, capture bytes, artifact or package. Its negative WORKER-12 receipt has one guest request, zero protected operations, `capture_published=false`, `denial_recorded=true`; errors/logs/receipts contain no Text or source bytes. No production export grant is defined by this default-deny policy. An eventual positive exporter needs an independently selected destination/capture-specific permission and fresh authorization at serialization, not reuse of `test.emit`.

Host-selected bound source-owner/closure/interface and WIT selectors remain separate from the original pure ingress; both must reject unselected or ambiguous bindings. The existing LIVE SlotRegistry is not this issuer: its `test.emit` checks are keyed by live slot ID, checked version, selected root epoch and frame; no standalone Worker Program maps to that host subject. The three normative specifications permit host-controlled authorization but do not select Worker owner, destination, epoch, adapter version, revocation state or protected ledger on behalf of the embedder. A host fixture explicitly selecting those facts can exercise real checked WIT/Wasmtime callbacks; it cannot become a production implicit grant. A `test.emit` issue never authorizes the separately counted, default-denied `test.code-export` operation.
