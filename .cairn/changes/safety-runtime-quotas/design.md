## Context

The Core-Bootstrap Node engine has `execute({limits})` and reports step/allocation exhaustion, but its public protocol sends inputs only and JavaScript has no selected Wasmtime fuel. The actual component compiler emits `core.wasm` alongside `component.wasm`; its import-free core retains private `noble$set-allocation-limit` and diagnostic exports. The guest has a fixed 1,048,576-byte initial memory, with generated heap beginning at offset 65,536; a separate 64-byte heap quota is meaningful without shrinking that memory. r[S-LANG-03]

## Decisions

### Decision: Host-selected Core execution budgets

**Choice:** Limit the production quota route to the four declared source-bound world exports. Require the complete WIT/world/export-source recipe, independently repeat the Noble frontend and backend compilation plus pinned component assembly, and reject a candidate Core unless every byte matches the freshly emitted Core before reading its private diagnostic. Reject any imported Core, instantiate a matched module in a fresh Wasmtime Store with normal memory and ample setup fuel, set generated guest heap quota before invocation, then set the exact fuel immediately before the selected guest call. The route never treats source mismatch, setup, validation or instantiation failure as execution success or quota exhaustion. r[S-LANG-03]

**Rationale:** The compiled Core artifact—not handwritten WAT or a guest-selected budget—contains the production Noble implementation and private allocator setter; Component Model imports cannot expose that diagnostic through WIT. The positive compute export returns I64(3) with ample fuel, while 1 fuel traps specifically `OutOfFuel` after instantiation. With ample fuel and quota 64, 56 ASCII bytes plus their eight-byte result record succeed, 57 fail allocating the record, and 65 fail copying; quota 76 permits 65. r[S-LANG-03]

### Decision: Distinct typed failure and cleanup

**Choice:** A private diagnostic flag is set only when the generated `$alloc` quota check fails. Check `UnreachableCodeReached` and that flag for allocation refusal, or exact `OutOfFuel` with zero remaining fuel for instruction-fuel refusal; otherwise report a distinct guest trap. Snapshot counters and no returned value before explicit trap cleanup or normal post-return, then require zero live generated bytes. r[S-LANG-03]

**Rationale:** Generic unreachable traps, failed module loading, host memory caps and exhausted runtime steps are not evidence of the two canonical limits. The generated counters measure guest heap only, not Wasmtime or host physical allocation; zero imports makes the selected no-callback claim observable. r[S-LANG-03]

## Risks / Trade-offs

- The production invoker rebuilds and byte-matches its candidate Core from the host-selected complete source recipe; the gate independently binds the accepted recipe, binary and CLI bytes. Trust in the compiler and pinned assembly remains explicit; this finite result does not prove engine, compiler or general semantic correspondence. r[S-LANG-03]
- The private Core diagnostics are not WIT guest exports. A trap may leave a busy guest; the host must reset diagnostic fuel and run explicit generated cleanup rather than claiming canonical post-return occurred. r[S-LANG-03]
