## Context

Node 24.13.0/V8 13.6.233.17-node.37 is the selected Core Wasm runtime. Its persistent memory/table/globals and immutable Program captures are real; its current external WAT assembly/validation per submission is not immediate reload. Instantiating on live shared imports before commitment can mutate shared state. K-DEF-01/02 freeze existing definition identities/dependencies and prohibit editing already prepared Program meaning. r[BE-LIVE-01] r[K-LIVE-01]

## Decisions

### Decision: Wasm bytecode, not a second Noble instruction set

**Choice:** A new opt-in checked source-to-in-process deterministic Wasm binary encoder and two-layer admission (independent Noble kernel plus exact VM byte validation/import/ABI correspondence) target the existing persistent Node/V8 engine. Existing Core WAT/external tools continue unchanged. Wasm bytecode does not imply interpretation: `--engine interpreter` is refused until an actual pinned no-JIT Wasm interpreter passes exact compatibility tests. r[B-LIVE-01] r[BE-LIVE-01] r[S-LIVE-01]

### Decision: Rebuild dependencies and swap snapshots, never mutate a Program

**Choice:** Reload checks a complete stable, host-selected file/import snapshot, re-resolves and rebuilds all transitively affected definitions with new immutable identities, validates their ordered stack, effect and capability ABI, prepares Wasm in isolated nonauthoritative state, and publishes one namespace generation only at a top-level safepoint. The next new top-level lookup sees new bodies; existing frames, old Programs/captures and their nested invocations see old resolved dependencies. No typed live slot inside old code, no re-execution or implicit state migration. r[K-LIVE-01] r[H-LIVE-01] r[H-LIVE-02] r[H-LIVE-03]

**Shared live ABI:** Shadow-stage against separate state, then instantiate the same accepted no-start/no-active-segment bytes against the selected long-lived shared live arena at a top-level safepoint. Pre-reserve disjoint bounded table/cell/data slots, install fresh functions through checked host-controlled writes, restore new slots on any prepublication failure, and publish only after complete no-effect install and final file-hash recheck. Old Programs, including aggregate captures, retain their original table slots; their declared effects still require current host authorization. r[H-LIVE-02] r[H-LIVE-03]

**Selected declared snapshot control (scoped runtime, not accepted LIVE evidence):** `ModuleSession::prepare` stages declaration/import with its prior module, alias and source-history snapshot. The live host clones that frontend, independently checks proof-bearing declarations before worker publication, and compares the candidate/watch sequence at the publication boundary; refusal preserves the old namespace and stack. Selected module versions and imports commit in one source-generation transaction, with compatible transitive dependents rebuilt on alias rebind. A saved old Program retains its resolved body and module identity while bound operations consult *current* host policy at invocation. Incompatible rebinds refuse without publishing a partial namespace. The declared lane uses its separately selected ordinary compiler/worker profile rather than silently importing the plain Core-live ABI. Its scoped real-child checks are not canonical LIVE-05 assurance.

**Bound adapter invariant:** A bound slot used by old compiled code keeps its immutable `(module, version, adapter, operation)` identity until no old Program can invoke it; a new module version cannot inherit that slot. The host may revoke the old identity's *current* authorization at a safepoint, but must not redirect its already-compiled request to a new version or keep an obsolete allow decision frozen in the old instance.

**Core code-retirement control (scoped runtime, not accepted LIVE evidence):** An old table span is reclaimable only after all owning backend roots are gone: current namespace versions, old module globals, saved Programs including aggregate captures, host-observed raw handles, and active frames. Plain Core live has its own 16-page owner ABI; the separate slot profile has a 20-page heap and different imports. The selected CLI registers exact installed spans, asks the worker to release superseded module roots only at idle, obtains `code_owners`, and calls `Compiler::retire_code` only after the worker proves zero owners, exact installed entries, stale-handle invalidation and physical clearance. Retirement receipts and first-fit reuse after ten selected reloads were observed in a real V8 child; old saved Programs still run. Unknown owners refuse. The table is reusable, but Core's append-only 4096-cell heap and text allocation are not reclaimed. No canonical LIVE-02/03 evidence follows from the scoped check. r[H-LIVE-02] r[H-LIVE-03]

**Guarded partial implementation:** Host-selected explicit file reload and direct definition admission use one bounded dependency-order Core rebuild and stage/publish path, exercised for acyclic `addone→twice→four`. `noble live watch --source` on Linux accepts only a cooperative complete save: paired same-directory `.tmp` creation/rename onto the selected basename, a directory-pinned regular single-link inode, bounded bytes and hash, and a prepublication candidate/watch sequence check. A new save supersedes an in-flight candidate; ACK discloses installed source bytes and a bounded ACK-time path observation, not perpetual freshness. Unpaired renames, in-place writes, aliases and invalid candidates refuse. A host-admitted guest proposal with current effective dependents refuses rather than rebuilding them; eligible dependent-free proposals use host publication. Saved Programs retain historic identities and dependencies. Scoped cycle refusal, declared snapshots, byte-gated external mmap refusal and Core code retirement are real-child controls, not complete source-bound H-LIVE-01/LIVE-02/LIVE-05 acceptance or interpreter execution. r[H-LIVE-01] r[H-LIVE-02] r[H-LIVE-04]

**Cooperative watch limit:** Linux [inotify(7)](https://man7.org/linux/man-pages/man7/inotify.7.html) omits directory child events for outside hardlinks and mmap/msync/munmap modifications, cannot identify the writer, and can overflow. The implemented paired `.tmp` save protocol is narrow: it authenticates a captured candidate at publication and avoids ACKing an observed later rename, but cannot enforce an immutable handoff against an external writable alias or promise path freshness indefinitely. An optional REPL before-submission exact-byte gate refuses changed or unverifiable selected bytes before guest entry; it neither monitors idle files on its own nor closes the gap after that finite check. Canonical LIVE watch scenarios remain absent/not-run. r[H-LIVE-01] r[S-LIVE-01]

### Decision: Guest proposals are inert until host admission

**Choice:** The opt-in live profile adds `self.generation` with declared `live.observe-generation` effect (ID 4), reading the invocation-pinned host *source* generation, and `self.propose` with `live.propose` effect (ID 3), accepting a checked pure `Program<[I64] -> [I64] ! {}>` and explicit expected I64 generation. A guest can construct that Program at runtime with an input-derived I64 captured by `quote` and combined with `[ + ]` through `compose`; this is a selected typed construction, not arbitrary source editing. The host alone selects an existing name and binds a one-use grant to its immutable checked originating definition identity and expected source generation via `--self-edit NAME --expect-generation N` or later host-only `:grant-self-edit NAME N`. Trusted compiler metadata supplies the lexical owner to the import; the guest cannot forge it with source or argument bytes. Proposal is pending, not publication, during the Wasm callback. After a normal top-level return, the host reifies only supported closed recipes to source, independently rechecks type/effect/kernel and exact Wasm bytes, shadow-stages, then compares current generation and owner against the grant before one atomic publication. A failed post-return candidate admission preserves the grant, namespace and completed invocation's stack/request history; an unauthorized callback is a real denied request, and a trap cancels pending work without erasing preceding effects. A rearmed grant for a new identity never authorizes retained old Programs. r[K-LIVE-02] r[H-LIVE-04]

**Selected input-dependent design:** `def evolve [ dup 18 - quote [ + ] compose self.generation swap self.propose drop 1 + ]` derives `def evolve [ 2 + ]` for initial input `20` and `def evolve [ 3 + ]` for input `21` in separate child sessions. The bounded targeted compiled-Wasm smoke checks those source shapes, not the full LIVE-09/10 conformance matrix or profile acceptance; canonical cases remain absent/not-run. r[K-LIVE-02] r[H-LIVE-04]

**Decoder boundary:** The candidate's checked pure I64→I64 type is only the first gate. The host reifier accepts bounded closed I64 literal/capture events and pure resolved arithmetic builtin IDs 4/5/6 (`+`, `-`, `*`), checking root/invocation signature identities and ordered stack transitions. Even a well-typed identity `[ ]` or a same-shape recipe with unsupported `dup`/`drop`/`swap`/`=` refuses after the guest returns, with its completed stack/request history and unused grant intact. Arbitrary Syntax and Program encodings do not become source. r[K-LIVE-02] r[H-LIVE-04]

**Provenance:** A guest-derived definition carries its own origin and derived source digest, not the unchanged selected source-file hash. Guest publication never writes or acknowledges file bytes. An explicit later `:reload FILE` is separately checked and can restore only when current type/effect/host policy permits; the first profile refuses an effectful file body's increase over a pure guest successor. Host-selected file reload/direct admission exercise the bounded Core-only rebuild with acyclic dependents; guest proposal refuses any current effective dependent, and incompatible replacements refuse without a stale ACK. Scoped indirect self-rebind/cycle refusal was exercised in live-child checks, but general proof, canonical LIVE acceptance and complete source-bound LIVE-02 acceptance remain open. r[H-LIVE-04] r[K-LIVE-01]

**Inspiration, not equivalence:** [Spector's Push overview](https://faculty.hampshire.edu/lspector/push.html) describes runtime code manipulation and autoconstructive programs that construct offspring code. Noble selects only an input-dependent, typed arithmetic Program proposal subject to host authority and independent admission; it does not adopt Push's per-type stacks, arbitrary code transformations, PushGP fitness selection or general evolutionary semantics. r[K-LIVE-02] r[H-LIVE-04]

### Decision: Resource-free first profile with explicit quotas and refusal

**Choice:** Preserve checked stack when ABI-identical; refuse resource-bearing stack or resource-positive import instead of inventing ownership migration. Cap source/read retries, check work, binary bytes, execution fuel/steps, recursion, memory/table/cells and retained old instances; retire unreferenced generations under accounting. A pre-invocation file reload refusal leaves old namespace/stack/authorizations untouched and runs zero candidate bodies. A post-invocation guest candidate refusal leaves the namespace and grant untouched and executes no candidate body, but retains the completed invocation's legitimate stack changes and host requests. Host effects of already running code are real and remain subject to independent policy. r[S-LIVE-01] r[H-LIVE-03] r[H-LIVE-04]

## Risks / Trade-offs

- A guarded in-process binary emitter/validation path exists for Core-only live admission, but no complete live-profile acceptance or source-to-Wasm proof exists for it. Isolated staging must not reuse an unchecked `install` against shared imports.
- Active calls delay publication; a finite wait/timeout refusal is honest, whereas zero-latency promise or stale next-call result is not. Saved Programs pin old code and may exhaust bounded retention.
- Strictly interpreted execution remains an optional separately gated engine, not a description of V8 flags or Wasmtime. Native C AOT, if specified separately, is not this Wasm live session. r[BE-LIVE-01] r[V-LIVE-01]
