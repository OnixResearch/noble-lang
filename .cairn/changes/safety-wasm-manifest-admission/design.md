## Context

S-CASE-16 canonically records `implementation: absent`, `execution: not-run`, `proof: open` until source-bound acceptance. The selected implementation interface is Core-only `noble admit-artifact WASM --effects CLAIMS_JSON [--source HOST_SOURCE] [--allow-effects ...] [--opt off|on]`. The source checker distinguishes effect IDs and latent quotation effects; Core Wasm imports `noble.test_emit` and `noble.test_abort` even when a given source does not call them. Distinct declared-module bound identities exist, but declared-binding artifact admission is outside this selection. For the current selected Core examples the emitter has no start and uses passive data/element segments; arbitrary submitted start/active segments refuse before instantiation. The boundary is **admit before instantiation**, not "infer all executed effects by equating an import list to a source effect list." The older runtime nominal allowlist and post-instantiation trace check alone cannot supply this correspondence gate. r[S-EFFECT-01] r[S-EFFECT-02] r[S-HOST-03]

## Decisions

### Decision: Finite source-bound candidate and independent host inputs

**Choice:** The Core host invoker independently supplies source bytes (`--source`), explicit allowed effect IDs (`--allow-effects`), optional effectful-host policy and pinned compiler/assembler/optimizer configuration (`--opt off|on`), distinct from untrusted `--effects` claims. No source means no independently established correspondence and no admission. Prepare host source with the actual resolver/checker and independent kernel acceptance, including all latent compiled quotations. Compile it with selected pinned options, validate *final* bytes and compare byte-for-byte with the submitted artifact before instantiation; no source hash, recipe hash, signature, filename, proof attachment or manifest substitutes for equality. Distinguish (1) source effect inclusion in invoker-allowed effects, (2) selected artifact/source correspondence, (3) reflected binary import interface and (4) admission-stage optional host authority. No declared-module binding policy is selected. r[S-EFFECT-01] r[S-HOST-03]

**Rationale:** A candidate may describe itself however it wishes. The invoker's separate choices and actual checked source plus exact final bytes make it impossible to turn an untrusted assertion of an empty effect set into the admission input, within this finite compiler/tool selection. This is measured correspondence, not a compiler-correctness proof.

### Decision: Actual binary import footprint, not a guessed effect list

**Choice:** Reflect actual validated final binary imports before linking: independently inspect exact module/field/kind, distinguish `noble.test_emit` → `test.emit` and `noble.test_abort` → `test.abort` from `noble.test_emit_bound` → bound `test.emit` and `noble.test_clock_bound` → bound `test.clock`. A bound function is known but unconfigured in this fresh Core host: refuse it, never synthesize a binding/script or ambient fallback. The canonical `test.emit` is a logical import identity mapped to Core's exact `noble.test_emit` binary field in its real artifact. Do not normalize unknown names, merge bound/unbound effects by prefix, treat nonfunction imports as guest effects, or infer invocation solely from an import's presence. The selected reflection does not independently decode function signatures: byte-exact equality with a final validated host-compiled pinned Core module establishes the selected signature/interface correspondence before instantiation. Mutated function type bytes must fail correspondence. Core functions imported unconditionally but unreachable for checked source are not fabricated source effects. Admission policy refuses disallowed checked source effects before guest execution; an unexpected callback outside the checked bound is an integrity failure, never authorization. r[S-EFFECT-01] r[S-EFFECT-02] r[S-HOST-03]

**Rationale:** Import reflection catches unexpected interface names/kinds and manifest lies; source checking and final-byte equality make unused Core ABI imports compatible with a checked empty source effect. Bound identities are not authority without selected binding admission. Admission-stage host-policy denial creates no guest request; a denial after an actual guest call would still count as a request under S-EFFECT-01, but that is not selected here.

### Decision: Nonexecuting precedence and isolated execution

**Choice:** Classify the canonical empty-claim/actual-`test.emit`/no-correspondence footprint specifically as `admission/effect-manifest-reject` without linking it. Preserve distinct refusals for malformed binaries, unsupported reflected interface, start/active segments, absent or mismatched host source/options/final bytes, source effects outside invoker-allowed effects, and missing optional effectful-host policy. Inspect and reject arbitrary submitted start/active segments before instantiation; current host-compiled Core examples have no start and passive segments. Never instantiate or invoke an untrusted candidate while deciding admission. Install only fully admitted final bytes in a newly isolated Core host with fresh memory/table/globals/traces and invoke the guest. Optional effectful-host policy refusal happens at admission, with zero requests and protected operations; there is no selected runtime-denied guest invocation. r[S-EFFECT-01] r[S-EFFECT-02] r[S-HOST-03]

**Rationale:** Instantiation can execute code and mutate imported state even if no exported function is called. The selected finite refusal must not rely on measuring side effects after they occur; positive acceptance must show a real compiled guest invocation and distinct protected-operation policy.

## Risks / Trade-offs

- This does not admit arbitrary externally built or declared-binding modules, prove a source-/backend-universal effect theorem, or prove a future generated start function harmless. Byte matching fixes one reviewed Core toolchain/options selection and runtime observations remain finite. Tool changes require new selection and evidence.
- Binary import names alone overapproximate possible source effects, especially the compiler's unconditional core ABI imports. A verifier that requires every imported function to appear in source effects would incorrectly reject pure and singly effectful compiler output; one that ignores a mismatched imported interface could admit a forged artifact.
- Bound `test.clock` and bound `test.emit` are identified then refused as unconfigured; scripted clock execution, declared-module binding/adapter policy, ambient authority and component profiles are not selected. Core `test.abort` abnormal termination and `test.emit` protected operation remain distinct.
