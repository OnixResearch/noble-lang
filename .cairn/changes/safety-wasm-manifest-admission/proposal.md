## Why

S-CASE-16 is still `absent/not-run`: its canonical Wasm-Draft input names actual `test.emit` imports, a claimed empty effect list, and no trusted correspondence. Existing validity checks and nominal import allowlists do not make an attached manifest authoritative, establish that the exact artifact came from the checked source, or prevent an import/start/active segment from acting during premature instantiation. This change selects a finite source-bound admission path, not a general backend theorem. r[S-EFFECT-01] r[S-EFFECT-02] r[S-HOST-03]

## What Changes

- Select Core-only `noble admit-artifact WASM --effects CLAIMS_JSON [--source HOST_SOURCE] [--allow-effects ...] [--opt off|on]`. Admit *exact final validated Wasm bytes* only when they match a fresh compilation of host-invoker-supplied source under pinned options, the complete checked source/latent quotation effect bound, reflected binary import names/kinds, and independently supplied allowed effects and optional effectful-host policy. Artifact metadata, digest, claimed effects, source label and recipe are never authorities. r[S-HOST-03]
- Distinguish actual `noble.test_emit`, `noble.test_abort`, `noble.test_emit_bound` and `noble.test_clock_bound` identities: Core admits only its own effects; bound imports are explicitly mapped but fail closed as unconfigured, not admitted declared bindings. Function signatures are assured by exact final-byte correspondence to the pinned host compilation before instantiation, not by independent signature introspection before correspondence. Core may import unused ABI functions; their physical presence does not prove source requests. Quoted code remains fully accounted even when latent. r[S-EFFECT-01]
- Reject the canonical forged `actual_imports:["test.emit"]`, `claimed_effects:[]`, `trusted_correspondence:false` at admission as `effect-manifest-reject`, with zero guest requests and protected operations, *before* attempting to instantiate the candidate. Admit separately checked positive source/bytes/policy cases and actually execute an allowed effect in an isolated host; deny policy without conflating authorization with effect inclusion. r[S-EFFECT-02] r[S-HOST-03]
