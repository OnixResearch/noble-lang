# Source-bound Worker Program v2 design

## Selection and identity

`worker typed` v1 remains pure and byte-compatible. `worker program` v2 is a separate opt-in host/guest contract; `worker-send.wit` remains MW2's distinct shell boundary. Admission retains the prepared ModuleSession, independently checked exported Program owner, exact instantiated input/output/effect witness, checked dependency closure, capture schema/value frames, and scoped recursive owner. The opaque runtime handle is bound to this retained session and cannot be reconstructed from package text, a hash or an artifact. The normalized identity is a semantic relation over checked recipe, exact typed captures, interface and dependencies; chosen wire bytes and optimizer layout are not identity.

## Builders and export/import

`adapt` checks source effects are included in a selected destination effect ceiling and retains the original recipe and original witness; the adapted value retains the destination witness separately. Heterogeneous list insertion/selection, duplication and composition check instantiated stack/schema equality and compose the declared effect witnesses without source compilation or host requests. All recipe expansion/allocation consumes one invocation meter; a failed operation publishes no program. Reflection is inert. Export requires an explicit destination-and-capture-specific host grant *before* package bytes leave the process. A versioned package contains finite indexed graph nodes, exact source-bound dependencies and host contract versions, checked schema identities, capture frames and scoped self-owner references; no live resource or host implementation is serialized. Import rejects missing/transitively wrong dependencies, foreign owners and unsupported revisions without fetch or partial publication, and rechecks the body even if the package carries a valid digest, accepted bit or artifact claim. A semantically equal package may use different artifact bytes; neither proof applicability nor authority transfers on import.

## Bounded execution and observation

The selected guest WIT transports opaque owner handles and bounded byte frames, not a WIT-claimed universal dynamic value. The host independently validates each frame against retained types and budgets before guest execution, counts pure guest steps and builder allocations under one task-owner meter, and distinguishes normal typed return, domain Result error, exhaustion, deadline with native work, permitted suspension, trap, cancellation and internal failure. Host operation requests are correlated to invocation and attempt IDs with requested/admitted/denied/completed/unknown events; output truncation carries an explicit omitted scope and never means no effects. Cancellation retires late results and does not undo prior effects. Host authority remains outside guest captures.

## Unsupported shape and dependency gates

Initial source work can support only finite, resource-free, checked source/data/captures with exact declared test host contracts. Resource captures, an unverified self owner, unknown effect/version, unsigned arbitrary binaries, arbitrary WIT dynamic signatures and unsupported recursive graph shape must reject explicitly. Full WORKER-03/04/09/12 execution requires the real guest WIT/component adapter and source-to-executed-VM correspondence; the present Node/V8 pure transition cannot stand in. Source-only checks are not guest execution evidence. The pinned Cairn wrapper invokes Nix, so creation/gates/validation wait for the exclusive heavy slot; these proposal files do not mutate canonical specifications.
