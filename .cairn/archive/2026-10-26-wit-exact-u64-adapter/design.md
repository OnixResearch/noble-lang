## Context

The accepted WI-WIT-02 preserves WIT distinctions and forbids silent loss; WI-WIT-06 requires selected Canonical ABI lowering/lifting. Canonical WI-03 is `Component-Draft/adapter`, `wit_type:u64`, decimal all-ones and `requested_implicit_target:I64`, expecting binding-stage `lossy-conversion-reject` and `wrapped_value_exposed:false`; its implementation is absent and execution not run. Prior M5/M6 receipts cover different selected signatures; the M6 hand-written WASI clock probe is not Noble `u64` support. This selection adds explicit bounded behavior without weakening WI-03's implicit-rejection expectation. r[WI-WIT-02] r[WI-WIT-06]

## Decisions

### Decision: Preserve type identity at binding, not ABI lane appearance

**Choice:** WIT parsing keeps `u64` as `RawType::U64` and resolution maps it to distinct boundary `Type::CheckedU64` through generated binding and signature checking. A normal binding requesting `I64` for this WIT scalar fails at binding, including the exact WI-03 all-ones input, without publishing a component or starting guest requests/host operations. No alternate implicit conversion, signed reinterpretation of the `i64` Canonical ABI lane, or conversion based on the particular runtime value is permitted. r[WI-WIT-02]

**Rationale:** Binding is independent of whether one eventual value happens to fit a signed 64-bit integer. The ABI's scalar storage width does not erase WIT's signedness or grant authority to interpret high-bit values as negative.

### Decision: Separate explicit checked adapter, narrow execution

**Choice:** The caller explicitly opts in through public `noble component compile-checked-u64 WIT WORLD NEW_DIR EXPORT=SOURCE ...` or `World::parse_checked_u64` instead of enabling an implicit mapping globally. The opt-in is not an authenticated host authority grant; `build_context` may record deterministic recipe identity, not authorization. The only selected world shape is import-free synchronous `export echo: func(value:u64)->u64`. Parsed `RawType::U64` resolves to distinct boundary `Type::CheckedU64`; only this explicit checked selection maps the latter to internal `I64`, never the default binding. **Any** import rejects at binding for this selected checked world, including a signed import alongside the unsigned export; `u64` imports remain unsupported in all paths. At the actual compiled component boundary, interpret the `u64` lane as unsigned and check `value <= 9223372036854775807` before signed `I64` use by the Noble source body. The emitted `$enter` prologue occurs first, so the guard does **not** precede all guest instructions. On exit, check the Noble `I64` result is nonnegative before publishing it as WIT `u64`. `0` and the upper representable bound round-trip exactly; the first high-bit value and all-ones trap at this guard with no result. A negative guest result must not publish as a huge `u64`. The negative path cannot claim success by converting to a negative source-body `I64`, trapping *after* source-body exposure, or skipping the actual ABI. r[WI-WIT-02] r[WI-WIT-06]

**Rationale:** The selected edge exercises useful interop while maintaining the existing no-loss rule. It neither adds general `U64` arithmetic to Noble nor changes the default type map; the public caller's explicit mode choice must be visible in the compile recipe rather than inferred from a signature or confused with an authority grant.

### Decision: Source-bound assurance and promotion boundary

**Choice:** The corrected active runners are `verification/wi03-final/gate.mjs` and `verification/wi03-final/postpromotion.mjs`, while the independent typed peer remains `verification/wi03/peer`. Preserve the original `verification/wi03/{gate.mjs,postpromotion.mjs,acceptance.json}` and its prior external receipt as historical. The new gate must first bind the canonical WI-03 id/input/expected projection to a real default binding refusal and separately run the explicit checked positive/high-bit controls through a compiled Noble component and independent typed Component Model peer. Add an export returning negative `I64` as an egress refusal control, unsupported `u64` import refusal, and **mixed signed-import plus unsigned-export** binding refusal. For the exact all-ones input, measure a real peer invocation with `Val::U64(18446744073709551615)`, trap and no returned result; retain the compiled module/WAT identity and checked compiler's source showing `$enter` prologue, unsigned ingress guard, signed `I64` source-body use and egress guard in order, under the explicit selected engine/compiler trust assumptions. Apply the same real ABI observation to first-high-bit control. The import-free world has no source-body entry counter: **source-body nonentry is unmeasured**, not an independently observed result or a receipt claim; the guard is not literally before all guest instructions. Retain exact versioned WIT, source revisions, compiler/host/peer/tool pins, component bytes/hash, actual commands and raw outputs, observed outcomes, and a digest of the prepromotion canonical case and source set. Freeze that source and store the first successful corrected receipt immutably before any WI-03 promotion or generated-view rewrite. Later canonical state/evidence may cite the corrected receipt only after gate success and a separate final-current-source replay; never rewrite historical M5 receipts, or call Cairn/document validation execution/proof evidence. r[WI-WIT-02] r[WI-WIT-06]

**Rationale:** A binding unit check cannot show actual component ABI ordering, and a typed peer's conversion alone cannot establish the compiled Noble/host path. The immutable prepromotion projection prevents circular self-attestation when the canonical record's state/evidence change.

## Risks / Trade-offs

- Wasmtime/Canonical ABI, selected compiler and host, toolchain and callback authenticity remain explicit trusted boundaries; passing scoped tests is not general ABI/compiler/engine refinement.
- `Val::U64` trap/no-result plus compiled source/WAT ordering is a scoped behavioral observation under engine/compiler trust; without source-body instrumentation it does not measure whether the source body began, and `$enter` prologue instructions do execute before ingress refusal.
- Values beyond the signed upper bound reject only in the separately selected explicit checked export; the default path rejects **all** `u64`→`I64` bindings. This selection rejects `u64` imports and excludes unsigned internal arithmetic, async, indirect parameters/results, aggregates, broad WASI and Component-Draft support.
- Source drift after the prepromotion receipt requires a new independently retained final replay; it must not mutate the frozen receipt or silently inherit earlier milestone acceptance.
