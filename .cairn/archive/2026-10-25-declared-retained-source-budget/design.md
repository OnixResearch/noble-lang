## Context

`Declared-Modules-v1` keeps immutable original whole-module source in each committed module and outside declarations in the session's length-prefixed history. On alias rebind it must reparse current outside definitions from those retained bytes, not a renamed display string, parsed tree, hash, or new caller-supplied source. Today aggregate retained bytes share the per-input `Limits.bytes` threshold. K-CHECK-07 still governs the separate input/checking budgets; H-REPL-02 governs failed-submission atomicity. The active `ma-language-prerequisites` profile adds signed self and declared Text, but does not authorize replacing retained source or increasing a single-input limit. DX-MODULE-01 and DX-MODULE-02 remain in force.

## Decisions

### Decision: Two independent host-selected ceilings

The CLI accepts `--retained-source-bytes N` only alongside `--declared-modules` on supported `compile` or `session` entry points, including their expressly selected declared-Text/signed-self variants. `N` is an integer in `1..=262144`; an explicit zero flag refuses as usage. Without that flag, retained aggregate capacity is exactly the selected per-input `--source-bytes` setting (historically 65,536). A declared invocation with the implicit aggregate set to zero remains a valid configuration with a closed quota, so a nonempty source exhausts without panic. An explicit positive retained value with a zero per-input setting is likewise a valid configuration, but no nonempty source passes the unchanged per-input limit. Ordinary `run`, ordinary `session`, standalone cursor and live profiles do not accept this flag or inherit the new capacity.

Internal declared-session constructors require a checked `RetainedSourceLimit`, rather than taking an unvalidated raw integer or widening `Limits.bytes`. `RetainedSourceLimit::new` admits the closed implicit zero bound and values through 262,144, rejecting larger values; the CLI imposes the **stricter positive** rule on an explicit flag before constructing it. `bytes()` exposes the validated capacity. Each input independently remains limited by its own `Limits.bytes`, whose maximum is 65,536, and its ordinary nodes/depth/work limits. Reducing `--source-bytes` cannot silently increase aggregate default, and increasing aggregate cannot admit an oversized single input. No calculator, runtime heap, execution fuel, host-operation or protected-work budget changes; existing K-CHECK-07 and H-LIMIT-01 remain in force. r[DX-MODULE-05]

A separate source-proof workflow must explicitly select its own 65,536-byte
retention setting, not silently inherit a caller's higher declared-session
setting. Raising a particular proof path to 262,144 requires separate user
authorization for that path, and does not claim the proof succeeded.

### Decision: Exact bytes, checked prospective accounting

The aggregate is the checked sum of the lengths of **every retained committed module's original whole-source byte sequence** plus the complete committed outside-definition history. The latter has exactly four framing bytes per outside declaration followed by its unchanged source bytes; a module-local definition is already included in the whole-module bytes and is not charged again as an outside declaration. A candidate module adds its full original input length; a candidate outside declaration adds `4 + input length` to the prospective aggregate. A submission without a retained definition adds zero. Every addition and conversion is checked; arithmetic overflow or an aggregate above the ceiling refuses before committing any namespace/history changes. Import rebind reads the exact original history entries, charges checking work under K-CHECK-07, and appends separately charged exact dependent-history copies with their own four-byte headers while retaining the earlier entries. Alias rebind neither evicts old modules nor replaces original source with hashes, normalized text, rewritten modules or only parsed forms.

The source-derived checker/proof path continues to bind exact original bytes, spans, immutable module/version/definition identity and digest to the same original source that later replay reparses. A shorter diagnostic snippet or a digest is never a substitute for retained source. A changed byte, forged span, mismatched proof owner or missing original body fails admission, not a permissive fallback. The entire prepared transaction (imports/aliases, transitive replays, newly bound module/definition, source history) publishes only after all capacity and static checks pass; a refusal retains the previous stack, registry, aliases, history and prior valid programs, and runs no candidate body under the existing DX-MODULE-01, DX-MODULE-02 and H-REPL-02 contracts. r[DX-MODULE-05]

### Decision: Unexecuted bounded conformance

New DX-14 is a declared-module admission scenario, separate from historical DX-08/09. Generate syntactically valid, semantically independent module/definition sources padded with ASCII whitespace to exact UTF-8 byte lengths, then independently count original bytes and each four-byte history header. With default limits, 32,768 module bytes plus one 32,764-byte outside definition consume exactly 65,536; replacing that outside definition with 32,765 bytes must refuse at 65,537 with unchanged state. At explicit 262,144, a 65,536-byte module and three 65,532-byte outside definitions (each with a four-byte header) exactly fit; one more byte must refuse. A single source of 65,537 refuses even at aggregate maximum. At `--source-bytes 1024` without retained opt-in, 512 module bytes plus a 508-byte outside definition and its header fit exactly at 1,024; 509 refuses. With explicit retained opt-in under that same 1,024 per-input setting, separately valid submissions may exceed 1,024 in the retained aggregate but cannot exceed 1,024 individually.

The scenario also exercises a checked alias rebind with a current outside dependent, its transitive replay and an older captured/qualified owner. It compares original raw source/digest/spans and rederived checked identity before and after successful replay; a hostile changed-source/forged-span/proof-source control must not pass merely because the displayed module name or hash-like metadata matches. Every refused candidate is followed by a valid submission on the same session to observe unchanged state. A framed declared-session input above its per-input cap but no longer than 262,144 bytes is drained exactly with a fixed 8 KiB buffer, refused as a counted parse-exhausted submission without candidate execution, then followed by a valid frame in the same session. A count beyond that safe drain ceiling, a malformed header or a truncated body remains terminal; this recovery does not extend ordinary sessions or `run`. Guest execution or independent proof is a later, separate evidence claim: neither writing DX-14 nor a passing document gate may mark it executed or proved, consistent with existing DX-MODULE-02. r[DX-MODULE-05]

## Risks / Trade-offs

- Larger persistent source is intentionally bounded but not a whole-process memory limit: parsed trees, diagnostics, Wasm and runtime allocations have independent quotas. A limit error must be classified as source-retention exhaustion, not a runtime trap or a proof mismatch.
- 262,144 is a maximum, not a new default; a launcher that wants the larger setting must explicitly select it and state its reason. Auto-deriving capacity from module count or proof work would weaken the opt-in.
- Existing DXM1 acceptance and original case receipts remain immutable. DX-14 starts `absent/not-run/open/unassessed` with empty evidence; future execution/proof promotion needs new source-bound measurements and separate assurance.
