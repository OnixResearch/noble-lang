# Declared-Modules-v1 design (contract gate, not implementation evidence)

## Profile and input boundary

`Declared-Modules-v1` is an opt-in, versioned post-M4 profile. Existing `Core-Bootstrap` parsing, identities, emitted Wasm, CLI and M4–M8 receipts retain their meanings. The first profile admits bounded UTF-8 source submitted in a session or as an explicitly supplied local source unit, with at most one module definition per unit, nonrecursive declarations, finite existing source limits (64 KiB/16,384 nodes/64 depth and explicit work/stack/type limits) and an explicit module count/constructor count charged before traversal. No evaluation during scanning, declaration registration, import resolution, binding, inference, acceptance, compilation, instantiation or linking; the only guest execution entry is an explicit invocation after the whole transaction succeeds.

The syntax below is a new source microprofile, NOT an existing accepted grammar. Source bytes and text literals are UTF-8; declared identifiers are ASCII lexical words, with the existing reserved-name and duplicate checks. Whitespace separates forms as in M4; `[` and `]` delimit bodies; keywords and arity delimit declaration forms. A non-ASCII declaration name is an explicit parse refusal. Scoped `@` in versioned module names and `,` inside bounded type constructors are part of this opt-in grammar, not new general Core-Bootstrap word characters. The implementation must reject unknown forms rather than interpret them as expression words:

```
module ledger@1 [
  opaque UserId I64 private
  variant Status Ready I64 public Failed Text private
  require emit Text -- ! test.emit
  export UserId
  export Status
  export handle
  def handle [ ... ]
]
import ledger@1 as account
account.handle
```

The module header's `@1` is the source interface version, not a mutable package locator. `module` body may contain only `opaque`, `variant`, `require`, `export`, and existing `def name [ body ]`; there is no top-level expression or initializer. `import name@version as alias` is a declaration, never an executable word. Admission rejects trailing expressions in a declaration, unbound/ambiguous names, duplicate exports/constructors, missing referenced versions, cycles, export of an undeclared name, and a module body executable at import time. A module can be supplied only through explicitly passed source units or an already prepared session registry, not ambient filesystem/network lookup. Reading local module files, if offered, belongs exclusively to the compiler CLI shell, is bounded and an explicit compiler-service file effect; it is not a guest operation. No portable package encoding/registry/remote identity is promised.

## Nominal types and visibility

The bounded type grammar is `opaque Name Base private|public` with `Base` one already checked concrete value type, or `variant Name Left PayloadLeft private|public Right PayloadRight private|public` with exactly two distinct constructor names and nonrecursive concrete payload types. Source types are exactly `I64`, `Bool`, `Text`, `Unit`, an already resolved local/imported nominal name, `Pair<A,B>`, `Sum<A,B>`, `List<A>`, and `Resource<test.counter>` (the latter only with an explicitly validated fixture resource kind for static negative tests). Generic type punctuation is inside one whitespace-delimited word; whitespace inside `<...>` is rejected. Nesting and total nodes obey the existing finite type/depth bounds. `Program` remains available through ordinary quotations but is not a source-declarable payload in v1. No user type variable, arbitrary N-way sum, recursive reference, representation alias, implicit conversion, invariant/refinement predicate, or resource-positive Wasm runtime is selected. Type declarations require a resolved module/version and remain immutable after commit.

Semantic type identity is the pair `(resolved immutable module identity, declaration ordinal)`; a distinct `UserId` and `OrderId` never unify even if both represent `I64`. Module identity is session-local canonical resolved declaration/interface/dependency composition including exact source interface version, constructor order/visibility, exported definitions and required operation identities/contracts, excluding display aliases, application adapter selection, formatting and build-only Wasm layout. A separately linked program identity additionally retains its selected adapter identities and contracts. Content equality may intern module identities; changing a module dependency/version changes its identity, while rebinding an adapter changes the linked-program identity but cannot retroactively change a prior checked program. Cross-process portable digest/serialization remains open. Runtime descriptor indexes are compiler-local and must never substitute for checked semantic identity.

`Name.new : Base -- Name` and `Name.into : Name -- Base` are explicit operations visible only inside the owner module for `private`; for `public`, both may be exported explicitly. Opaque grants no implicit unwrap or general field access. This v1 opaque declaration imposes no value-range invariant; a later invariant-bearing wrapper would need an enumerated checked construction/decoder protocol before admitting it. `Name.Left : PayloadLeft -- Name` and `Name.Right : PayloadRight -- Name` are visibility-controlled constructors. `Name.match` consumes a value plus two typed branch quotations in declared constructor order: its caller must own the schema, or every constructor and its payload interface must be public/exported. An exported type with even one private constructor is not externally matchable; use an explicitly exported owner-defined eliminator instead. Its checked branch stack effects must have one identical complete ordered output stack and conservatively include both latent effects; every constructor is covered even if private to an outside caller. There is no wildcard, partial match or name-based fallback. Unknown or duplicated branch, wrong payload/interface, schema/version mismatch, unavailable private arm, or unmatched constructor rejects before execution. Lowering uses the existing managed-memory tagged sum and compiled `case` shape, retaining nominal source/checker identity and validated runtime schema/tag metadata. A private constructor cannot be synthesized or inspected by a foreign module through a raw tag, Sum coercion, decoder, reflection, or WIT import.

`Ty::Nominal`/a validated schema descriptor retains the resolved identity, exact representation/alternatives and visibility. All recursive eligibility predicates (`Data`, discard, duplication, quotation capture and serialization) inspect the representation/payload transitively, not the opaque name or exported visibility: a `Resource<kind>` nested in an opaque wrapper, either variant payload, aggregate or Program capture rejects the relevant operation. Treat source resource references in this slice as static negative fixtures tied to an explicitly validated host resource kind; this gate does not promise resource-positive nominal Wasm execution. Resource ownership remains M5's contract. Semantic identity and schema matching happen in kernel acceptance, not solely frontend inference or AST rewriting.

## Module interface and binding

The finite interface contains `(module-id, source-version, exports with exact checked types/effect bounds/visibility, required operation identity and signature, resolved dependency ids)`. Module imports resolve once against an explicit immutable registry snapshot; checked definitions and compiled closures retain those ids. Rebinding a display alias affects only future resolution, never earlier accepted programs. Import/link checks source-version and exact resolved interface, schema identity, export visibility, operation input/output stacks, full effect identity and effect inclusion, and actual adapter binding identity before publication. A requirement is not an authorization token; linking/instantiation does not call an adapter, guest body or host authorization service. An absent/incompatible binding, unavailable adapter contract, unsupported import initializer, cycle, or stale preparation fails closed with no ambient fallback.

The first real host operation is `test.emit : Text -- ! {test.emit}` only. Source `require emit Text -- ! test.emit` binds a local module spelling to that exact versioned semantic operation/effect; a supplied application adapter declaration must independently match its ordered interface and effect bound. The accepted environment cannot infer effects from display names or erase the direct `test.emit` effect; kernel separately derives it for invocation and quotation. A and B may share display text, but their binding identities are distinct. The host dispatch keys on the retained adapter identity from the admitted binding, never a mutable name. At invocation, the ordinary host authorization policy independently denies or permits, records the request/effect and prevents protected work on denial. The adapter may be a test fixture, but the guest request must originate from compiled Noble/Wasm and cross the real host boundary; no host interpreter or fabricated request trace.

## Cutover through production components (planned; not changed here)

1. `crates/noble-contracts/src/source/{lexer.rs,parsing.rs,resolution.rs,preparation.rs,inference/,emission/}`: extend the scanner and top-level form parser with these declarations, immutable registry, exported visibility and alias snapshot; resolve construction/match/required-operation uses to exact ids before inference; emit finite untrusted candidates carrying schema refs and effect witnesses. Preserve existing `def`/expression paths and session transactional behavior.
2. `crates/noble-kernel/src/{types.rs,types/impls.rs,shapes.rs,words.rs,contracts.rs,acceptance/,execution/mod.rs}`: validate nominal schema graph and ids/bounds; add checked constructor, explicit conversion and exhaustive match rules; independently derive complete branch interfaces/effects and recursive eligibility; check complete linked interface and all specialized definitions. Never trust frontend tags, claimed effects, visibility, or executable payloads.
3. `crates/noble-wasm/src/source/{types.rs,plan.rs,plan/operations.rs,emit/functions.rs,admission.rs}` plus the selected `runtime/{data,operations,reflection}.wat` where necessary: recheck accepted schemas, intern distinct nominal descriptors, emit tagged construction/elimination into compiled functions and preserve recipe semantic identity. Resource-positive nominal values remain rejected by the backend in this slice. Do not convert a nominal to structural Sum/I64 at the checking boundary.
4. `crates/noble-cli/src/{core.rs,core/worker.rs,core/runtime/}`: install explicit versioned module sources and adapter bindings transactionally, keep immutable A and B dispatch slots across rebind, authorize on request, retain observations and zero import-time calls. Use the existing real Wasm worker; no separate source interpreter.
5. Acceptance runner and scoped tests: source-declaration guest integration, static adversarial checker/link controls, compiled Wasm positive/denied runs, exact state-preserving refusal and regression of Core-Bootstrap/M4–M8. Source inventory, extraction/assurance changes, generated docs and ledgers are separate evidence work after actual execution; this contract change makes no completion claim.

## Exit evidence and compatibility risks

DX-03 must execute each declared variant: same-layout nominal mismatch, equal identity acceptance, private constructor denial, foreign private-arm match denial, missing variant arm rejection, all-arms compatible stack acceptance inside owner or on an all-public schema, and transitive resource dup/drop/capture refusal, with zero guest requests. DX-08 must execute matching/missing/wrong-input/wrong-effect/import-initializer variants through real module source/linker, proving zero guest and host requests, zero protected operations and no acquired authority. DX-09 must compile and invoke actual source: retained version-A adapter is requested once and denied by independent host policy, `test.emit` remains in its effect accounting, no protected work occurs and rebound version-B is never called. Include positive compiled invocation using matching binding, positive nominal variant match, cross-module exported value use, distinct module-version identity, stale snapshot and hostile candidate controls. Evidence must identify source/tool revisions and actual Wasm worker observations, not proxy fixture verdicts. Cases remain absent/not-run until execution; proof/refinement/portable package claims remain open.

Highest risks are extracting new recursive nominal type walks via Charon/Aeneas, preserving nominal descriptors across quotations/reflection/session snapshots, module identity versus mutable alias reuse, runtime tagged representation versus checker types, and conflating the fixed M4 `test.emit` slot with per-adapter identity. Prefer versioned isolated admission and explicit ABI dispatch to silent modification of historical profiles. No validation, static type witness, or successful link grants host authority.
