## Context

S-CASE-06 in `specs/conformance/safety-cases.json` is a `Resources-Draft/runtime` design: source `"main.rs" fs.read`, declared effect `fs.read`, live `Directory` in `invocation-1`, `read_right:false`; expected `stage:authorization`, `outcome:denied`, `guest_requests:1`, `request_trace:["fs.read"]`, `protected_operations:0`. Its implementation is absent, execution not-run and proof open. S-EFFECT-03 separates effect descriptions from host authority; EV-CASE-03 requires denial after a declared, counted request rather than static effect rejection. Existing M5's always-denied `store/api#read` and S-CASE-02's host-owned byte region do not implement filesystem access.

## Decisions

### Decision: Exact preopened file and host-only Directory

**Choice:** Select `noble-test:authorized-fs/bounded@1.0.0`: WIT imports `fs.read(path: string) -> result<list<u8>, string>` and exports `read-file() -> result<list<u8>, string>`. The compiled Noble export contains `"main.rs" fs.read`; its effect is the actual versioned read import, represented as `fs.read` in the canonical request trace. Production `noble component read-fs COMPONENT HOST_PREOPENED_FILE READ_RIGHT WIT WORLD EXPORT=SOURCE ...` first parses the host-invoker-selected complete WIT/world/export-source recipe, independently prepares/compiles the selected Noble source, and byte-compares the exact emitted component with the candidate **before** opening a file or creating an owner/grant. Mismatched recipe/component refuses with CLI status 2 at admission, not as canonical authorization denial. Only a matching candidate proceeds: the host invoker preopens one vetted regular File without reading contents during setup, mapping **only** the exact guest UTF-8 key `main.rs` to it. Guest strings are looked up by exact key, never interpreted as native paths or resolved under ambient working directory, and there is no fallback/alias/relative traversal. The host owns a fresh invocation-specific **logical** Directory table owner and context over that one opened File; it does not preopen an OS directory. WIT passes neither a Directory resource nor a native path or preopened-file descriptor to the guest. The host can grant READ or none independently of liveness and effect annotation. No general directory enumeration, writes, symlink/path traversal, WASI filesystem world or arbitrary file access is selected. r[S-EFFECT-03] r[S-RES-03]

**Rationale:** Canonical source has one `fs.read` request and no guest-visible owner operand. Byte correspondence prevents substituting an arbitrary component while relabeling its source/effect before the host makes any file available; a separate mismatched-recipe control must not be conflated with the one-request canonical denial. A host-only capability rooted in an already opened exact file can meet this case without silently treating a source effect, host path string or resource-table index as permission. Opening/validating the host-selected regular file is setup, not a protected content read; an observed zero protected read on denial must include all paths that could actually read file bytes.

### Decision: Authorization and owner lifecycle before content access

The report's authorization stage and denied outcome come from a retained host-side READ-right failure in the resource Table, never from the guest's `Result` error text. A source-matched guest returning the string `denied` without that failure is an adapter-level guest result, not an authorization observation; the request trace and protected-read counter retain their actual callback values.

**Choice:** At each import call, append the actual bounded callback request to the trace first and check the retained owner table identity/context/kind/generation/liveness and independently host-selected READ right via `Table::validate` at the serialized host boundary, then the exact key. A missing grant or bad path/owner denies before a protected file-content read. In the no-READ canonical invocation return a typed denial, classify it as `authorization/denied`, and record precisely one guest `fs.read` request, no content reads and no protected operations; do not claim check-time rejection or zero requests. For a fresh READ-granted invocation of the **same compiled component**, authorize the exact local key/owner/right combination, begin the table borrow before work, perform one accounted protected read operation from the already opened host File with at most 4096 output bytes, complete it and release or retire the host owner once. Reading at most one additional sentinel byte detects a file that grew past the bound; oversize is a bounded **postauthorization** failure, not a zero-read authority denial. Host-claim/path/READ refusals must read no bytes; oversize may have read up to 4097 bytes but must not return them as a successful 4096-byte value. On denial, domain error or trap, do not depend on guest continuation to retire the owner; repeated cleanup and stale callbacks must not release twice or resurrect authority. r[RA-STATE-01] r[RA-CLEAN-01]

**Rationale:** Host ownership and host-granted READ are independent predicates. `Table::validate` of that retained right is this bounded filesystem profile's authorization boundary; `Table::begin`/native access and the measured callback/read/outcome remain distinct. The service-specific `Authority::authorize_from_trusted_host` Plan/facts and guest-visible one-shot service witness are not invoked or claimed for a single host-retained local file capability; there is no new general H-AUTH service-policy implementation. A request trace is not authority or proof of a successful read. The canonical denial has zero protected operations even though the host preopened a vetted File before guest execution.

### Decision: Source-bound acceptance before promotion

**Choice:** The owner runs the exact canonical negative through actual Noble compilation and production Wasmtime linking with the complete matching host-selected recipe; a separate granted run of those same compiled guest bytes must return the host fixture's safe bounded bytes with one accounted protected operation and one owner retirement. Retain actual bounded callback trace, independently observed protected-operation and owner counters, exact file fixture and host-selected path/grant, WIT/component/CLI/source identities, tool/policy bindings, command output and failures. A mismatched WIT/world/source recipe must reject at admission with status 2 **before** opening the file or establishing a Directory/READ right, with zero guest requests and protected operations. Probe rights=none with live owner, unknown/`../main.rs`/absolute/alias guest keys, stale/foreign-context/wrong-kind/wrong-generation/retired host claims and oversized fixture on the same production decision boundary; guest-visible path probes may use separately compiled controls, while hostile table claims are host-injected because WIT exposes no Directory handle. Every **authorization/path/owner** refusal must have zero protected file-content reads; an oversized granted file is instead a separately labeled bounded-read failure. Do not mislabel a pre-invocation or static failure as canonical authorization denial. Freeze immutable **prepromotion** acceptance against the prepromotion source and case state before any native delta sync or scenario promotion. Only after terminal PASS may the owner preview/execute Cairn sync, promote exact S-CASE-06 state/evidence, regenerate views/ledger/status, and run distinct postpromotion staged-source document/Cairn checks and archive. Leave all earlier receipts and runners untouched. r[EV-CASE-03]

**Rationale:** A Cairn structural gate, a stubbed host callback, an interpreter, or a happy-path returned byte string would not establish the canonical authorization-stage denial or real file access. Source-frozen acceptance and later generated documentation have different source scopes; neither can be substituted for the other.

## Risks / Trade-offs

- This is a single-host, single-preopened-regular-file profile, not an ambient filesystem sandbox. Host vetting, open-file stability, local revocation facts, Wasmtime ABI/linking, file I/O and compiler correspondence remain explicit assumptions. A successful finite run does not establish arbitrary path safety or atomic authorization across remote systems.
- A fresh source-bound owner-law proof, Octet policy/provenance acceptance and actual Rust → Charon → Aeneas → Lean refinement are not supplied by this change; all remain OPEN. Do not infer formal proof from checked resource-table controls or from accepted runtime evidence.
