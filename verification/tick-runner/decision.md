# Issue #128: bounded sequential I64 tick decision

**Protocol:** `noble-tick-i64/v1` remains an opt-in library API. The continuation rule in [continuation-criteria.md](continuation-criteria.md) was committed as `d32895a` **before** the first timing or allocation observation; its SHA-256 is `f99c55aba4f36917d3ff9b5674a2c1725b09c0c3aa42804b27ff021d5c23fbab`. No cutoff was changed after observing data. The final measured clean source is `597d228cea3f8e2e7f8f35400aa101ae13bd1c21`, tree `257bc150c869657e746d646a46eec83b0d6acbeb`.

**Decision:** Finite protocol correctness passed its executed tests and independent trace replay. **Further optimization exploration is NO-GO under the frozen rule.** This does not disable the already opt-in API, assert a compiler speedup or reopen any previous result. The ordinary-graph warm-tick advantage is below the required 10% in every 512/4096 case, whole-trace runner medians exceed ordinary graph medians, native break-even is undefined because native has lower marginal tick cost, and arm-specific peak RSS is unavailable. The measured retained estimates alone cannot establish comparable peak heap usage. The timing test executable has debug assertions enabled; Cargo profile and exact optimization level are reported `unknown` by the compiled test because Cargo did not expose those values to `option_env!`. These shared-host observations cannot certify release performance or a deadline.

## Exact retained observations

- [Raw compiler-lab NDJSON](evidence/trace.ndjson) and [independent BigInt model replay](evidence/replay.json): 11 tick requests (six accepted), three control-update requests (two accepted), three reset requests (two accepted) and seven refusals; every operation's ordered state/output and active epochs checked; raw trace SHA-256 `a4be16fca6e6e5a0f8d297c1d9c24a79ff725e3978133cffe1532ad3a9778a83` (7,323 bytes). The replay proves only finite agreement with this exported model; its model-export hash and identity labels do not independently prove correspondence to all Rust graphs or authorize execution.
- [Matched three-arm benchmark](evidence/benchmark.json): three scenarios (one-state add, two-state asymmetric, subtracting reset) × 32/512/4096 accepted ticks; identical ordered operations, one untimed complete-tuple replay for each arm, 11 interleaved rounds, 10 warm rounds, separate graph prepare/reset, control admission/activation, first tick, first after update, first after reset, warm tick, refused calls and cleanup. It records wall time plus best-effort benchmark-thread CPU nanoseconds (short traces may be null owing to scheduler accounting resolution), exact workload bytes/digest, source/tool/executable identities and an actual CPU model. `VmRSS` is a shared-process after-run observation, not arm-specific peak RSS.
- [DHAT allocation summary](evidence/allocation.json) and [nine exact process profiles](evidence/dhat-final/): three arms at zero, 32 and 512 ticks, with raw JSON, stderr/stdout, tool and binary digests and relevant allocation points. At 512 ticks: runner 1,921 blocks / 122,034 bytes; ordinary graph 2,420 / 122,853; native 1,848 / 81,175. These totals include harness and fixture allocations; zero-length subtraction is diagnostic, not phase-level or per-tick attribution. The existing evaluator still allocates output/preflight storage. There is **no allocation-free claim**.

The [Lean model](../../proofs/foundation/NobleFoundation/TickRunner.lean) proves scoped selection, one logical commit, refusal preservation and explicit reset state **for the self-contained model only**; its inventoried concrete fixtures include ordered-input refusals. The Rust integration suite and independent Node replay are finite tests, not a Rust-to-Lean refinement theorem or backend-wide soundness proof. Cancellation is sampled by the evaluator at layer boundaries; a signal after the last probe is not observed for that tick. No GPU, concurrent update, effect rollback or real-time claim follows.

#14's historical Phase C **STOP** remains (warm W3-L graph about 9.71 µs vs host-native 1.27 µs), and #41's independent-row batch **NO-GO** remains (its frozen 4096/65536-row speed and resident-growth rule failed). Reopening either requires its own issue, preregistered rule and independent retained evidence. A new sequential optimization attempt likewise requires a separately committed preregistration, exact optimized artifact profile, comparable arm-specific peak memory and source-bound matched traces that satisfy every frozen gate; this decision does not permit moving this rule's cutoffs.
