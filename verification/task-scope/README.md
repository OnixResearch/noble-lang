# Bounded host-owned M6 task scopes (issue #115)

The scope prototype is deliberately a host-side/test-only composition layer over the existing M6 task table. It does not change `async_tasks::Table`, add a workspace unit, or alter the CLI's production `ExecutionScope`.

`../../proofs/foundation/NobleFoundation/TaskScope.lean` imports the #46 `TaskInterleaving` model and defines the policy bound: two children, one explicit 15-action alphabet, and sequences through depth 3 (3,616 enumerated sequences, including the empty sequence). Its theorems cover host identity/membership, attachment-order results gated by delivery, refusal, cancellation and late completion, settlement order, capacity, and close/release behavior. The Lean policy does not model host payload values. The in-bound wake trace reserves one wake while retaining shared task capacity; cancellation releases that reservation without releasing the retiring task. Normal completion traces project to the imported #46 `reaches` relation. `../../proofs/foundation/NobleFoundation/TaskScopeCorpus.lean` is generated by the adapter test from observed M6-table replay values; a freshness test requires exact equality with the committed file.

The adapter is included by `crates/noble-kernel/tests/m6-interleaving.rs` using local `#[path]` modules. It exercises the real `async_tasks::Table` for both completion orders, incremental second-admission refusal and caller-input preservation, both sibling-completion/cancellation orders, stale/foreign identity refusal, accounting and observations, input retention across refused cleanup and release after accepted cleanup, and inherited ownership when the host scope is dropped. This is finite test evidence, not a Rust-to-Lean refinement theorem.

## Reproducing the retained evidence

Run from a clean committed worktree with the policy-selected Node 24 binary. Supply the approved Cargo and Lean command executables through `NOBLE_CARGO_RUNNER` and `NOBLE_PROOF_RUNNER`; point `NOBLE_TARGET` at an external build directory and `TMPDIR` at a private temporary directory. The output directory must be new, outside the repository, and have an existing parent:

```sh
NOBLE_CARGO_RUNNER="<absolute path of the approved Cargo command>" \
NOBLE_PROOF_RUNNER="<absolute path of the approved Lean proof command>" \
NOBLE_TARGET="<new directory outside the repository>/target" \
TMPDIR="<private temporary directory>" \
"<absolute path of the policy-selected Node executable>" \
  verification/task-scope/run.mjs \
  "<new directory outside the repository>/task-scope-run"
```

The supplied command executables run the repository's offline, locked `cargo test` commands for the existing `m6-interleaving`/`m6-async` tests and CLI `worker_program_guest` regressions, then `verification/ci/lean-proofs.sh` through the pinned proof lane. The runner writes `receipt.json` only after all commands pass and verifies that the source tree did not change while they ran. Copy each receipt into `verification/task-scope/receipts/` under a dated filename and commit it. Retain one receipt from this run before Cairn archival as the documented replay, then rerun after archival and retain a second receipt binding the archived package path. Each receipt binds its clean source commit/tree, the content digest of the Cairn change package, the model, generated corpus and foundation registration files, and the declared child/alphabet/depth bounds. It records the foundation check report's digest, source commit, source tree, theorem count, Lean version and binary hash, and allowed axiom set; each command's result lines are recorded separately.

## Evidence boundary

- **Model:** kernel-checked policy obligations over the imported finite #46 model, at the bound and alphabet recorded in the receipt.
- **Adapter/runtime:** finite Rust tests that drive the production M6 table and assert its returned observations and decisions.
- **ExecutionScope:** the existing single-invocation CLI regressions are rerun unchanged; they are not an implementation of this new group scope.
- **Assumptions/non-claims:** one serialized host owner, unique host-issued scope identities, authentic host observation of native stop, and a live retirement registry. No nesting, more than two children, fairness/liveness, native authenticity, eventual completion or cleanup after host death, production integration, or model/adapter refinement is claimed.

The Cairn design and `RA-GROUP-01` through `RA-GROUP-06` remain the source of the accepted host-scope contract; RA-CLEAN-04 remains the existing cleanup boundary.
