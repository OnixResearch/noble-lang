### Finding details

**F-01 (Blocker, LSLOT-02): incomplete projection, while coverage is claimed.**

`project02` (`projection.mjs:165-280`) emits 25 entries. The case has 51 canonical leaf paths, and these 22 have no entry at all:
- `input.harness`
- `input.base.registry_epoch_1.A.version`
- `input.base.registry_epoch_1.B.interface.{input,output,effects}`
- `input.base.root_A_entry.pin_operation`
- `input.base.root_A_entry.caller`
- `input.transitive_variant.independent_fixture`
- `input.transitive_variant.registry_epoch_1.A.{version,interface.input,interface.output,interface.effects,body}`
- `input.transitive_variant.registry_epoch_1.B.{version,interface.input,interface.output,interface.effects}`
- `input.transitive_variant.registry_epoch_1.C.interface.{input,output,effects}`
- `input.transitive_variant.root_A_entry.ordered_host_issued_inputs`
- `input.transitive_variant.root_A_entry.borrow_pass_through`

The gate loads only the base authority (`gate.mjs:320`), so the transitive interfaces could not be compared even in principle. Nothing in `gate.mjs:335-366` checks that the entries cover the case.

The records nevertheless claim complete coverage:
- tasks.md:25-26: "projects every machine-expressible canonical `input`/`expected`/variant field".
- tasks.md:34-36: "All 21 machine-expressible fields match".
- The README rule, and the LSLOT-02 `workload_binding` ("Exact … projection over 21 observed field(s) …").

The behaviour itself looks right. In the hash-verified raw evidence (`LSLOT02-transitive-A-B-C.jsonl`):
- the transitive authority is C `[I64]→[I64]` with no effects;
- B is `[I64, LiveRef<I64,I64,pure>]→[I64]` with effects `[live.dispatch]`;
- A is `[I64, LiveRef<I64,I64,pure>, LiveRef<I64+LiveRef<I64,I64,pure>,I64,live.dispatch>]→[I64]` with effects `[live.dispatch]`;
- the root binds the refs in the order C, B, A with `I64:20`.

These match the canonical transitive design semantically. The defect is in the gate and the claim, not the runtime. The likely reason the fields were dropped is that `normalizeType` (`projection.mjs:31-33`) cannot spell nested refs in the canonical form.

**F-02 (Blocker, LSLOT-09): a LIVE-change witness that cannot fire.**

`liveWasmUnchanged` (`gate.mjs:286-288`) checks two things: the working-tree file hashes the same as `HEAD:` that file, and `git status` on that file is empty. The gate has already asserted the whole tree clean (`gate.mjs:122-124`), so both conditions hold whenever the gate runs.

To demonstrate this, I committed an edit to LIVE-03's `expected.outcome` in `clone-mut` and evaluated the exact expression. It gave `liveWasmUnchanged = true`, which projects `historical_LIVE_01_to_10_changed = false`, recorded as `observed`.

B-LSLOT-01 requires that historical LIVE status and evidence stay unchanged *by this design*. Note that the sibling `cairn/live-cases` branch is promoting LIVE-01, LIVE-06 and LIVE-07. A real witness therefore needs a baseline scoped to this change, not to HEAD.

**F-03 (Major, LSLOT-02): a lookup witness that cannot fire.**

`projection.mjs:263-266` tests `/slotId/` against `recipeSha256 + semanticContext + programValueId`. Those strings are built only from hashes and fixed words:
- `semanticContext` is built at `slot-engine.mjs:576-583`:
  `definition-source:<sha|unavailable>:selection-source:<sha>:artifact:<sha>:occurrence:<n>:recipe:<sha>`.
- `programValueId` is `artifact:<sha>:cell:<n>`.

The literal `slotId` can therefore never occur. Mutant 02-M8, which embeds the slot name `B` in the semantic context, stays `observed`.

**F-04 (Major): constant or self-referential entries recorded as `observed`.**

- **LSLOT-02 versions** (`projection.mjs:199-200`, `220-221`): `base.registry_epoch_1.B.version` and `transitive_variant…C.version` compare `'B-v1:[ 1 + ]'` with `` `B-v1:[ ${bodies.B1} ]` ``, where `bodies` is a hard-coded constant (`projection.mjs:173`). Likewise, `versionLabel` (`projection.mjs:52-55`) asserts constant equal to constant. The lane's actual install sources are never read.
  - The LSLOT-02 assumption "Version names come from … the exact selected source bytes" is therefore false.
- **LSLOT-02 ordered inputs** (`projection.mjs:210-212`): the canonical value of `ordered_host_issued_inputs` is replaced by a count (`3`). The types and order of `I64:20`, the B ref and the A ref are not compared.
- **LSLOT-09 `input.controls`** (`projection.mjs:551-559`): the same literal array appears on both sides, so no lane data is read. Mutant 09-M6, which removes both lanes' control descriptors, stays `observed`.
- **LSLOT-09 `input.harness`** (`projection.mjs:545`): compares the fixture with a literal.
- **LSLOT-01 `publication.candidate`** (`projection.mjs:126`, `131`): both sides are built from the lane's own `replacement` source, which is hard-coded at `live_slot_capture_legacy.mjs:19`. The `[ 1 + ]` body in `slot.target` comes from the fixture's definition (`projection.mjs:103`, `117`, `121`), not from the installed original.
- **LSLOT-01 `generic_caller`** (`projection.mjs:108-112`): the canonical prose is replaced by `{instruction, borrowed_input, effects}`. The caller's input order `[I64, LiveRef]` and its output `[I64]` are not compared.

**F-05 (Major, LSLOT-02): observable facts declared, and one dispatch counted twice.**

The canonical `interleaving` entries are `declared` (`projection.mjs:227-233`). But the runtime reports them:
- the old root carries `control_events = [{control_id:"1", operation:"publish", scope:"B", epoch:"2", outcome:"published"}]`;
- the lane asserts this, together with `ack.root == entered.root` (`live_slot_nested_roots.mjs:116`, `124`, `128-136`).

`base_root_A_B_selections` calls `selection(base, base.old_root, 'B', '1 +')` twice (`projection.mjs:241-242`). `selection` reads only `trace.at(-1)` (`projection.mjs:176-178`), so the first B dispatch is never examined and the dispatch count is never checked.

Mutants that the projector does not catch:
- 02-M1b: the first B dispatch selects B-v2, with a self-consistent trace;
- 02-M3: only one B dispatch is recorded;
- 02-M4: no publication inside the old root.

Only the lane's assertions, through its exit status, would catch them.

### 2. Are the refusals of LSLOT-03, 04, 06 and 07 honest and correctly reasoned?

All four are honest. Every one is recorded as `unobserved` with a specific reason, nothing was relabelled `declared`, and no mismatch was hidden. The classification of each is below.

| Case | Field or variant | Classification | Reasoning |
|---|---|---|---|
| 03 | `same-layout-different-resource-schema` | **Case-design defect** | The protocol's input-only override yields `[Account@2, I64] → [Account@1, I64]`. No checked candidate inhabits that for a linear nominal resource within a `[test.emit]` ceiling without a conversion primitive. The lane's constructible analogue (both sides Account@2) was refused. A conversion primitive would be new language scope. |
| 03 | `effect-ceiling-widened` | **Case-input defect** | The case names `fs.write`, which the pinned live-slot host cannot select (`live_slot_resource_ref_admission.mjs:23-24`). The runtime already implements the refusal (`slot-registry.mjs:323`, `'effect-ceiling-widened'`). The lane's non-canonical ceiling control observes it: an empty-ceiling slot refuses a `test.emit` candidate (`live_slot_resource_ref_admission.mjs:130`). Needs an owner amendment to an expressible effect. |
| 03 | `unknown-host-contract` | **Case-design (stage) issue** | The candidate is refused at source resolution, before admission, which is the desired safety outcome. It cannot be constructed "at admission" in a source-only candidate profile. Admitting artifact-level candidates would be new runtime scope. |
| 03 | `generic-caller-underdeclares-dispatch` | **Case-design defect** | The language delta has the checker *assign* `E ∪ {live.dispatch}` (`.cairn/changes/explicit-live-references/specs/language/spec.md:19`), so no caller can claim fewer effects, and reflection observes the assigned set. A program value containing `slot.invoke` cannot be formed either: `[ slot.invoke ]` is refused (LSLOT-06's direct-quotation-capture variant). This is not a runtime gap unless the owner wants declared effect annotations. |
| 04 | `successful_rollback_requires_…_evidence` | **Runtime gap the change must still implement** | No evidence operand exists on publish or rollback, and proof-required publication is refused unconditionally (`live_slot.rs:1472-1476`, `2763-2767`; `slot-engine.mjs:1427-1431`). The registry already takes an `evidence` argument (`slot-registry.mjs:324-327`), but the CLI never supplies it. This is the same capability LSLOT-05 needs, so it is tied to template identity (F-09). |
| 06 | case-level `guest_requests: 0` | **Case-design defect** | It contradicts the accepted `valid-borrow` variant, which needs one guest request. `invalid_variants_guest_requests` already expresses the intent. |
| 06 | `serialize`, `forge` (and `ref_data`, `ref_authority`) | **Case-design defect** | These are unconstructible by construction: the delta forbids the conversions and the profile has no such word. The property holds by absence. The case must state what evidence of absence it accepts. |
| 06 | `aggregate-capture`, `export-or-return`, `retain` | **Case-design defect** | Each is refused *earlier*, inside the case's own `static-and-invocation-boundary` phase: a `Pair<…LiveRef>` root type is refused, a LiveRef-typed output is refused, and no ref credential is ever exposed. My probe confirms refs are out-of-band operands, not stack values: `swap swap` over `[I64, LiveRef]` is refused with `actual [] I64`, because only the I64 is on the stack. The case should accept the earliest refusal. The gate's conservatism is honest. |
| 07 | `publication-without-grant`, and the "or evidence" half | **Runtime gap** | Same as LSLOT-04: the proof-present premise cannot be constructed without evidence-carrying publication. The other three variants are observed. |

Net position:
- LSLOT-04 and LSLOT-07 need runtime work in task 2: evidence-carrying publication. That is coupled to the template-identity work LSLOT-05 waits for, so owner decision 8 needs revisiting.
- LSLOT-03 and LSLOT-06 need owner-approved case amendments. They are not runtime gaps of this change.
