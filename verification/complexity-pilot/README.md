# Packed-layout complexity pilot (issue #80)

## Decision and claim boundary

**GO** for the current-toolchain, finite model and its Rust-generated acceptance/refusal corpus. The result is deliberately limited to the function-level model and finite witness inputs. It does not prove a costed algorithm, establish a Rust implementation-refinement theorem, or claim that the Lean `List` operations have the Rust checker's cost.

The three claims remain separate:

| Level | Evidence in this slice | Status |
|---|---|---|
| Function/model | `NobleFoundation.PackedLayoutEncoded` gives finite graph/table inputs, a total decoder, an injective self-delimiting encoding, exact encoded bit length, and `validateEncoded_agrees`; `NobleFoundation.PackedLayoutCorpus` kernel-decides real emitted fixtures and Rust-refusal-confirmed mutations. | **Proved** for the stated model; **tested** for the finite Rust fixtures. |
| Algorithm/cost | The operation inventory and asymptotic accounting below describe `layout::check`'s current Rust passes. They are not a Lean cost theorem. | **Documented obligation analysis**; a Complexitylib costed-machine proof is deferred to the isolated project below. |
| Implementation/refinement | The Lean model does not encode Rust serde bytes, compiler/build-key derivation, or the provenance and invariants of `CheckedGraph` metadata. | **Open**. No Rust-to-Lean refinement theorem is claimed. |

**Decision evidence and criteria.** Issue #43 changed the checker from nested duplicate/entry scans to one register sort and ordered-map count passes; the current source documents the resulting bound, and the retained cost report exercises both deep-chain and balanced shapes. The finite list encoder/corpus can be checked with the repository's current Lean toolchain, while the complexity library requires a separate v4.36.0-rc2 closure. This slice therefore admits only the finite-model and source-accounting work that is directly grounded in existing code and retained measurements; it does not promote source comments or benchmark speedups into a formal asymptotic claim.

**Reopen conditions.** Revisit the algorithm-level status only after the isolated project below can be built with its exact pins and an explicit costed-machine statement accounts for every input field, pass, and refusal path in the table. Revisit implementation-level status only with a byte/decoder correspondence and a checked proof boundary for the `CheckedGraph` metadata consumed by `layout::check`; more finite fixtures or faster measurements alone do not satisfy either condition.

`PackedLayoutEncoded` represents nodes, layer assignments, failure nodes and every declaration table as finite lists. Its layer lookup is a bounded list lookup, not the issue's unbounded `Nat → Nat` cost oracle. The encoding is a model format, not the Rust wire format. The corpus is generated by the existing `schedule_correspondence` target; the exporter checks each mutated declaration against `layout::check` before emitting Lean.

## Cost-obligation table for `layout::check`

Let `n` be graph nodes, `m` interface slots, `L` checked layers, `c` declared constant rows, `s` declared slot rows, and `v` the combined byte lengths of the two revision strings. The register vector has exactly `n` entries before the register pass; the layer and failure-suffix vectors are checked to have lengths `L` and `L+1` before their passes. Define `k = c + s + 2L + 1`, counting the table rows whose lengths are traversed. The current implementation's operation accounting is:

| Pass / source anchor | Work and refusal path | Dominant cost |
|---|---|---|
| Revision, compiler revision, layout key (`layout::check`) | Compare both declared strings, then compare the fixed-size `Digest`; refuse with `StaleRevision`, `StaleCompilerRevision` or `LayoutKey`. | `O(v + 1)`; the digest comparison is constant-size. |
| Register-map shape and ownership (`register_map`) | Scan nodes in order, checking each `u32` register and collecting non-guard `(register,node)` pairs. Sort the pairs once, then scan adjacent windows to find aliases and preserve earliest-node refusal order. Refusals: `RegisterMapShape`, `GuardRegister`, `RegisterOutOfRange`, `AliasedRegisters`. | `O(n log(n+1))` time and `O(n)` scratch space; register words and pair keys have fixed widths. This replaces a per-node search through prior registers. |
| Dense count and reserved-one register (`check`) | Count non-guard nodes in one graph pass and compare the count/highest register. Refusals: `RegisterCount`, `OneRegisterHeld`. | `O(n)` time, no table-sized scratch allocation. |
| Constant table (`table_counts`, `check`) | One graph pass builds a `BTreeMap<(u32,u64), usize>`; each declared row removes its matching key; one additional graph pass counts constant nodes. Refusal: `ConstantTable`. | `O(n log(n+1) + c log(n+1))` time; map holds at most `n` keys. The key components are fixed-width. No repeated graph scan per row. |
| Interface-slot table (`table_counts`, `check`) | One graph pass builds a `BTreeMap<(u32,u32), usize>`; each row performs a lookup and marks its slot in `covered`; one final graph pass counts input/parameter nodes. Refusal: `SlotTable`. | `O(n log(n+1) + s log(n+1) + m)` time; map has at most `n` keys and `covered` uses `O(m)` bytes. A returned `CheckedGraph` has one node per declared slot (`check_slots`), so `m ≤ n` for this boundary. |
| Layer shape/order (`check`) | Check vector lengths in constant time, then verify each layer's start/end against its predecessor. Refusals: `LayerShape`, `LayerOrder`. | `O(L)` time. |
| Failure-suffix minima (`check`) | Allocate the per-layer and suffix-minimum vectors, scan graph nodes using the stored checked-layer assignment, fold minima backwards, then compare `L+1` declared entries. Refusals: `LayerShape`, `FailSuffixMismatch`. | `O(n+L)` time and `O(L)` scratch space. |
| Instruction coverage (`layer_coverage`) | Count instruction-emitting nodes by their stored checked layer, then verify the declared layer ranges against those counts. Refusals: `LayerShape`, `LayerCoverage`. | `O(n+L)` time and `O(L)` scratch space. |

For a `CheckedGraph` produced by `check`/`check_with`, and with its slot invariant `m ≤ n`, these passes give `O(n log(n+1) + (c+s) log(n+1) + L + v)`, equivalently `O((n+k) log(n+1) + v)`. Scratch space is `O(n+L)` (the table maps and sorted pairs are bounded by graph nodes; layer vectors by `L`). The additive `v` is explicit because revision fields are Rust `String`s and equality can inspect the supplied bytes; claiming a pure node-count bound while admitting unbounded revision strings would omit input work. In the currently selected build, the expected revision values are fixed constants.

This is a source-level accounting, not a new benchmark or a kernel-checked complexity result. `sort_unstable` is the one sort pass; the two `table_counts` calls are ordered-map passes. The constants/slots are not rescanned once per declared row. Per-entry early refusals can shorten these traversals; the bound describes the accepted path or a late refusal.

## Trust boundary and exclusions

`layout::check` receives an opaque, immutable `&CheckedGraph`. It reads `graph()`, `packed_layout_key()`, `layer_count()` and `layer(NodeId)`; it does not regenerate the schedule or recompute graph typing/layers. The private `CheckedGraph` fields include the graph, logical ID, re-derived types, layer vector/count, input facts, abstract summaries, slot-node mapping, parameter slots/layout key, and packed-layout key. Their correctness and construction cost belong to `check::check_with`, which runs policy/budget, topology, slot, type, fact, layer and retained-byte checks before returning the value. In particular, `check_slots` requires every interface slot to have exactly one input/parameter node, supplying `m ≤ n` for this boundary. This pilot does not prove those Rust invariants in Lean.

Excluded from the `layout::check` bound are graph admission and `CheckedGraph` derivation (`check::check_with`), layout construction and scheduling (`Compiled::new`), serialization/deserialization, evaluation/Wasm execution, and the cost of computing identity/build keys. The model's `revisionOk` and `failNodes` are explicit model inputs, not Rust-format fields. F32 and guard-specific model correspondence is outside the emitted corpus. A validated `PackedLayout` is not evidence that the Rust bytes/refusal order are refined by the Lean model beyond the listed finite fixtures.

## Negative claim/encoding controls

The generated `PackedLayoutCorpus.lean` includes three kernel-checked controls:

* `nodesOnlyEncoding_is_not_injective`: omitting the revision metadata makes a valid and stale-revision input indistinguishable under a node-only encoding.
* `finiteFixtureLookup_misses_model_accepted_extension`: a finite layer-count lookup over the two real fixture counts misses a model-accepted input with an additional empty layer. That extension is deliberately model-only and outside the `CheckedGraph` correspondence boundary.
* `node_count_does_not_measure_encoded_input`: the same graph-node count can require a longer complete encoding; the accepted metadata extension increases the encoded input by 79 bits.

These refute those particular incomplete encodings/size claims; they do not prove any asymptotic bound. The controls live in the same generated file as the Rust corpus so freshness checking covers their definitions. The relevant Lean declarations are inventoried in `proofs/foundation/inventory.json` and summarized in `proofs/foundation/README.md`.

## Empirical context from issue #43

The previously retained [validation-cost report](../ngraph/validation-cost-2026-11-05.json) measures four existing families: a 16,384-node deepest chain; four and sixteen deepest chains (65,533 and 262,129 nodes, each with 16,384 layers); and a 262,144-node balanced tree with 19 layers. It reports five-run, one-thread release medians and layout-check speedups of 46×, 54.5×, 158.3× and 549.7× respectively for the post-`#43` implementation. Its own non-claims say the result is reporting-only, from one host/run, with no cross-hardware bound. This pilot adds no timing threshold and treats the measurements as empirical context, not a proof.
