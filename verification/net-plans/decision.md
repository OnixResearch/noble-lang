## Correctness scope and reopen conditions

**Model proof:** the kernel-checked foundation model preserves the selected revision-3 right-hand side for both orientations of OP2, OP1, DUP and ERA. The compiled local image commits as one inets `HNet` firing, with observational pre-commit stutters, frame preservation outside declared agents/wires, and one abstract `CStep` under the stated matching/redex premises. The independent version-one Lean writer/parser roundtrip covers any bounded/admissible field image, including I64 payloads and both endpoint kinds. Five fixed Lean byte images decode: OP2 output-only, OP2 with one newly active external peer, wrapping OP1, DUP and ERA. A model physical executor decodes each image, and kernel proofs establish exact post-state and equality to the corresponding `Plan.commit.toNet` for all five; the nonempty OP2 case also proves the directed-pair worklist. These fixed model images are not exported Rust bytes or a theorem for every checker-admitted image. Generation-tagged slots, stable output labels, queue orientation and journaled pre-commit/rollback are modeled separately. A universal Rust-to-model refinement is **not** proved.

**Rust implementation:** the independent decoder/checker and safe arena/worklist executor cover the exact emitted bytes, reuse/fresh/free mapping, payloads, boundary writes, ownership and reservations. Unit controls include forged bytes, stale generations, alias rejection, duplicate publication, interruption and failed reservation with rollback; the all-family test checks complete observations, interactions and resource counters. These are finite tests, not a universal correspondence proof.

**Boundary admission:** two distinct auxiliary ports may target different ports of the same external agent (the queued-neighbour fixture exercises this). An auxiliary loop back into either consumed agent or two captured ports naming the identical endpoint is rejected as `plan-boundary-alias`; no claim is made for those inets shapes. The Rust candidate is rebuilt and compared up to agent renaming against a checked DAG-origin graph before reduction, so the tested profile does not admit those loop/duplicate-endpoint cases. The Lean inets model's broader loop cases do not extend Rust admission.

**Output identity contract:** the physical model carries a stable abstract free-port label separately from each output's mutable arena target. Its projection derives reciprocal output-to-agent wires from the target and keeps the free-port label fixed when an admitted plan retargets the output. Identifying an abstract free port with the currently referenced agent port instead would make OP2/OP1/DUP refinement false; the emitted-image proof must preserve this distinction.

**Queue-order contract:** Rust appends one canonical generation-tagged physical pair per reciprocal principal connection after the existing pending worklist. Vendored inets records **both directed orientations** of that pair in `principalPairs fired.wires`; its abstract `Plan.commit` prepends these entries before pending work. The physical projection therefore expands each current Rust pair into two abstract entries and drops generation-stale pairs. Given a checked publication inventory, Lean proves tail append/head prepend have equal directed-pair multisets (`List.Perm`) and physical queue publication cannot change `toNet`; the nonempty OP2 image proves one actual two-orientation case. **Whole-`HNet` equality of ordered worklists is false** when both pending and published parts are nonempty. This is not a proof that every Rust scheduling policy selects the same next pair; inets normal-form/equal-count results still require their own invariant and termination premises.

**Open correspondence obligation:** prove that **Rust's** compiler emits the modeled `ngraph-net-plan/1` bytes for each admitted rule and that its independent decoder/checker admits only images whose slot/port/worklist mutations (saved boundary, generations, marks, reservations, rollback and overflow refusal) project to the model's one abstract rewrite. The remaining general Lean sublemma is: for every checker-admitted OP2/OP1/DUP/ERA image and representable live layout, `PhysicalState.executeCheckedImage` preserves the untouched frame, produces `Plan.commit`'s agent/wire/free projection, and gives a directed-pair worklist permutation (including reuse/fresh slots, external peers, reverse orientations, existing work and alias refusals). Five fixed instances discharge those conclusions, not the universally quantified sublemma. A separate unproved Rust correspondence must bind the actual compiler, checker and executor transitions to this physical model. The obligation statement is **DONE**; universal implementation refinement is **OPEN**; hardware/concurrency are outside the issue.
