## Correctness scope and reopen conditions

**Model proof:** the kernel-checked foundation model preserves the selected revision-3 right-hand side for both orientations of OP2, OP1, DUP and ERA. The compiled local image commits as one inets `HNet` firing, with observational pre-commit stutters, frame preservation outside declared agents/wires, and one abstract `CStep` under the stated matching/redex premises. The model separately proves the exact version-one Lean writer/parser roundtrip for any bounded/admissible field image, including every I64 result payload and both endpoint kinds. Four representative OP2/OP1/DUP/ERA byte images decode exactly and their result symbols agree with the selected rule; these images are Lean fixtures, not an actual Rust plan-byte export. It also models generation-tagged slots, ordered outputs/queue and journaled pre-commit/rollback. These are **not** the missing theorem that Rust's emitted byte plan performs the corresponding physical arena rewrite.

**Rust implementation:** the independent decoder/checker and safe arena/worklist executor cover the exact emitted bytes, reuse/fresh/free mapping, payloads, boundary writes, ownership and reservations. Unit controls include forged bytes, stale generations, alias rejection, duplicate publication, interruption and failed reservation with rollback; the all-family test checks complete observations, interactions and resource counters. These are finite tests, not a universal correspondence proof.

**Boundary admission:** two distinct auxiliary ports may target different ports of the same external agent (the queued-neighbour fixture exercises this). An auxiliary loop back into either consumed agent or two captured ports naming the identical endpoint is rejected as `plan-boundary-alias`; no claim is made for those inets shapes. The Rust candidate is rebuilt and compared up to agent renaming against a checked DAG-origin graph before reduction, so the tested profile does not admit those loop/duplicate-endpoint cases. The Lean inets model's broader loop cases do not extend Rust admission.

**Output identity contract:** the physical model carries a stable abstract free-port label separately from each output's mutable arena target. Its projection derives reciprocal output-to-agent wires from the target and keeps the free-port label fixed when an admitted plan retargets the output. Identifying an abstract free port with the currently referenced agent port instead would make OP2/OP1/DUP refinement false; the emitted-image proof must preserve this distinction.

**Queue-order contract:** Rust appends newly discovered generation-tagged pairs after the existing pending worklist. The abstract inets `Plan.commit` prepends newly active pairs before its pending worklist. Lean proves these two lists are permutations and that appending physical queue publications cannot change the observed net; **whole-`HNet` equality of their ordered worklists is false** when both parts are nonempty. The physical model follows Rust append order, and refinement compares `toNet` equality plus pending-pair `List.Perm`. This is not a proof that every Rust scheduling policy selects the same next pair; the inets normal-form/equal-count result applies under its own invariant and termination premises.

**Open correspondence obligation:** prove that **Rust's** compiler emits the modeled `ngraph-net-plan/1` bytes for each admitted rule and that the independent Rust decoder/checker admits only images whose physical slot/port/worklist mutations (including saved boundary, generations, queue marks, reservations, rollback and counter-overflow refusal) project to the model's one abstract rewrite. Specifically, the missing Lean premises of `PhysicalTransaction.commit_refines_if_projected` are `transaction.current.project.toNet = (Plan.commit H (Plan.compile H r hRule) rest).toNet` and a `List.Perm` of their projected worklists after applying the **decoded** OP2/OP1/DUP/ERA image; their four rule-shape cases have not been proved. A second unproved Rust correspondence binds actual Rust execution steps to the physical model. The explicit obligations are documented (**DONE** as an obligation statement), but the implementation refinement proofs remain **OPEN**; hardware/concurrency are outside the issue.
