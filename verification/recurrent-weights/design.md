# Design: bounded exact threshold networks

This is a CPU-only, Noble-owned construction experiment, not a neural checkpoint or a general recurrent runtime. Each transition is a finite layered `ngraph-f32/0` graph whose Param snapshot contains exact binary32 coefficients. Bit cells are exactly `+0` or `1`, making finite Boolean gate construction possible without converting arbitrary I64 values to F32. The format's checked `Bit` facts and the existing Param snapshot identity/stale refusal are the relevant substrate; these facts do not by themselves prove this design correct.

Two fixed programs separate arithmetic from routing. The accumulator encodes state and input as 64 little-endian bit cells and implements modulo-$2^{64}$ addition with a bit-level full-adder/carry chain. The routing program swaps two 64-bit stack words. The independent checker consumes only the declared source transition, codec and candidate graph/weight snapshot. It evaluates the candidate over the declared finite domain and compares decoded results with source semantics; the compiler is not an oracle. A faulty candidate must be detectable by this same path.

The baseline is explicitly a host loop around a one-step stateless graph. Host-managed state is serialized between calls; there is no persistent model state. The subsequent unrolled artifact is a statically composed graph with explicit intermediate transition boundaries, capped at four steps. It is not presented as recurrent state held inside weights. Both retain immutable weights and mutable state separately. Only complete state snapshots at transition boundaries may resume, and restoration is bound to the program, codec/configuration, weight identity and remaining budget.

The host supplies input cells, initializes state, schedules graph execution, enforces a maximum of 1,000 semantic steps, checks cancellation at transition boundaries and observes decoded output. It must not calculate carry bits, addition, or the stack permutation. There are no host effects or external inference runtimes in this slice. Stock runtime coverage is therefore none. Any performance claims are limited to the exact CPU evaluator path measured; finite differential tests are not formal proofs, and no evidence transfers automatically to another decoder, runtime, kernel or configuration.

Continuation is governed solely by `criteria.md`; that file was committed before any measurement. No runtime, activation, normalization, rounding, token-selection or decoder-margin behavior outside the exact bit-cell graph is implied. This design refuses unsupported state representations and configurations rather than coercing them.

## Subsequent stock-runtime comparison

The later comparison is separately frozen in `stock-runtime-criteria.txt` and retained from the lint-clean source in `receipts/2026-11-14/stock-runtime-701c64e.json` (the preceding `stock-runtime-60c449b.json` is immutable historical evidence from before the lint-only API refactor). The test-only exporter traverses the **checked** Noble graph and Param snapshot; it refuses operators outside Input, Param, exact-bit Const, F32Select and BitGuard. It emits ONNX IR 10, standard opset 18: Gather for individual input cells, initializers for exact-bit weights, Equal/Where for selects and Concat for ordered observations. The only host transition work remains input encoding, state handoff, budget/cancellation checking and output decoding. It neither implements carry nor swaps the stack on behalf of the ONNX graph.

ONNX has no Noble bit-guard/refusal operator. The bounded exporter omits BitGuard nodes under the restricted input/weight contract: the host refuses non-exact input bits, validates immutable snapshot bytes and model digest, and each emitted select chooses between two exact-bit operands. This closure is specific to these graphs and values; no general proof of Noble guard preservation or ONNX floating-point correspondence is claimed. The selected ONNX Runtime CPU provider executes the emitted model with optimization disabled and one thread. The stock-runtime result does not extend to a dense GEMM network, sparse optimized network, another provider, or a persistent recurrent/KV inference state.

The stock host-loop checkpoint contains the completed semantic transition index (`0..=1000`), exact state words, program/codec/model identity and remaining budget. Initial, request-end and noninitial boundary continuation are exercised; mid-graph and out-of-range indices refuse. This runtime has no attention/KV state: extra hybrid fields refuse rather than simulating a working hybrid restore. In particular, a checkpoint missing recurrent state refuses even when KV-like or scratch material is offered. An actual hybrid serving contract still needs its own state ABI and proof/evidence.

## Model-carried recurrence in the stock runtime

The subsequent model-state target is separately frozen in `model-state-criteria.txt` and retained in `receipts/2026-11-15/model-state-d4978b5.json`. It wraps the same admitted one-step graph/Param snapshot in a standard ONNX `Scan` body. The body receives `body_state_bits` and `body_token_bits`, evaluates the checked transition, and returns both `body_next_state_bits` and `body_observation_bits`. The outer model accepts `initial_state_bits` and all declared `scan_inputs`, and emits `final_state_bits` and an observation at every completed step. The accumulator carries 64 state cells and receives 64 input cells per step; the stack swap carries 128 cells and receives an **unused, mandatory exact +0 dummy token** per step because the `Scan` ABI requires a scan input. No other token shape/value is admitted. All cells are exact binary32 +0/1, with 64 little-endian cells per word; arithmetic remains wrapping unsigned 64-bit addition with no intermediate F32 integer cast. There is no activation, normalization, rounding of nonbits, threshold margin, or bf16 path.

The state relation at completed index `k` is `decode(body_state_bits[k]) = source_state[k]`. Initialization encodes the declared source state, the checked one-step graph maps it and the declared input to the next state, the observation decodes that same next state, and execution halts/refuses outside the predeclared 1,000-step bound. A single `InferenceSession.run` executes all 1,000 free-running transitions: ONNX `Scan` carries state between its body iterations, and the host cannot supply a correct intermediate state. Teacher-forced comparison instead makes 1,000 separate one-step calls using source states and is never called free-running. The host serializes initial/final state at request boundaries, encodes inputs, validates exact bits, enforces budget/cancellation before the call, and decodes observations; it does not add or swap source words. ONNX sessions do **not** persist state across separate calls, so “model-carried” means loop-carried inside one model execution, not hidden persistent KV or attention state. At request boundaries the state tensor is explicit and is subject to the complete checkpoint/identity rule.

The immutable Noble **Param snapshots** are 8 bytes for the accumulator and 0 for routing (the ONNX models also contain graph constants and indices); the complete ONNX models are 47,499 and 13,467 bytes, and mutable state tensors are 256 and 512 bytes respectively. The 1,000-step sequences carry 256,000/4,000 input bytes and return 256,000/512,000 observation bytes. The receipt includes compile/export and load times, wall/inference times, host calls (one per free run), 1,000 Scan steps/tokens, skipped work (zero), RSS samples/peak as a **process-memory proxy, not measured ONNX arena scratch**, and a same-run 1,000-call stateless ONNX host-loop comparator. No performance threshold or speedup claim transfers from this single stock CPU timing sample to dense/sparse kernels. The selected ORT 1.23.2 CPU provider is optimization-disabled and single-threaded; ONNX Scan and exact-bit closure are exercised, not kernel-independent theorems. A live compiler/runtime correctness proof and hybrid serving capture remain outside this experiment.
