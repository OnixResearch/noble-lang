# Ordered binary32 gradients: `grad.rs` against the Lean reference (issue #45)

This lane compares the gradient functions in
[`crates/noble-ngraph/src/grad.rs`](../../crates/noble-ngraph/src/grad.rs) with the ordered binary32
reverse-AD reference
[`NobleFoundation.ReverseAD.Ordered`](../../proofs/foundation/NobleFoundation/ReverseADOrdered.lean).
It runs `forward` and `backward` for `R = f32` over inputs, parameters, constants, addition,
subtraction and multiplication. The comparison is finite and differential evidence on one host and
target; it is not a refinement proof.

## How the expectations are made

[`verification/foundation/grad-ordered/corpus.lean`](../foundation/grad-ordered/corpus.lean) prints
[`corpus.txt`](../../crates/noble-ngraph/tests/grad_ordered/corpus.txt) from the Lean model alone, so
every expected forward value and gradient is independent of the implementation under test. Its 306
cases are:
- the six fixtures of `ReverseADOrdered.lean`: two stored orders of a cancellation, the repeated
  operand, repeated output seeds, a negative-zero seed, and an exact case;
- 300 graphs generated by SplitMix64 from a fixed seed: one to three slots, up to two constants,
  one to eight additions, subtractions and multiplications over earlier nodes with possibly
  repeated operands, and one or two seeded outputs.

The value pools are chosen for absorption at `2^24`, exact cancellation, signed zeros, subnormals and
overflow. The Rust checker refuses a node that reaches no output, so the generator turns every
otherwise unreached node into an output with its own seed. That also seeds slot, constant and
interior nodes.

Regenerate from `proofs/foundation`:

```sh
lake env lean --run ../../verification/foundation/grad-ordered/corpus.lean \
  > ../../crates/noble-ngraph/tests/grad_ordered/corpus.txt
```

## What the lane checks

[`grad_ordered/differential.rs`](../../crates/noble-ngraph/tests/grad_ordered/differential.rs) is a
module of the `train_admission` test target. Its two tests:

- `forward_and_backward_match_the_lean_reference` builds each graph with `GraphBuilder`, checks it, and
  runs `grad::forward` and `grad::backward` with `DerivOptions::default()`. It compares every node's
  forward value and gradient bit for bit. Every NaN encoding is one observation class, as in the
  binary32 model.
- `corpus_detects_each_seeded_fault` re-implements the ordered reverse pass over
  the corpus's reference forward values alone. Unmutated, it must reproduce every expected gradient.
  It then applies seven single-rule faults, each of which must disagree with at least one case.

[`differential.mjs`](differential.mjs) records the receipt on a clean tree. It runs the lane inside
`nix develop`, requires both tests to pass and the compared case count to equal the corpus header,
and binds the corpus, generator, model, binary32, lane and `grad.rs` digests.

## Retained run

### `713e02bd`: [differential.json](differential.json)

The run used `rustc 1.96.0-nightly (ac7f9ec7d 2026-03-20)` on `Linux 6.18.54 x86_64`, from a clean
source. All 306 cases agree: 2,270 forward values and 2,270 gradients. 63 cases involve non-finite
values (infinities or NaN from overflow) and 196 have a repeated operand. The receipt binds the
model's clean foundation receipt `956d8ca07`, whose 7 theorems include the kernel-checked fixtures.

| Seeded fault | Cases that detect it |
|---|---|
| ascending traversal | 207 |
| overwrite instead of accumulate | 271 |
| repeated multiplication operand presummed | 3 |
| seed assigned instead of accumulated | 127 |
| subtraction accumulates `+gn` | 194 |
| multiplication uses its own operand's value | 155 |
| fused multiply-add accumulation | 1 |

The fused multiply-add and presummed-operand faults are each detected by few cases. Those counts are
recorded rather than assumed, and a regenerated corpus that loses them fails the lane.

## Boundaries

- No extraction or refinement relates `grad.rs` to the Lean model; the comparison is finite
  evidence on one host, target and toolchain.
- The fragment is inputs, parameters, constants, addition, subtraction and multiplication. Affine
  terms, `relu`, guards, indexing and surrogate policies are outside it.
- The seeded faults are test-local re-implementations with one rule changed, not an exhaustive
  fault model.
- No binary32 gradient error bound is claimed.
