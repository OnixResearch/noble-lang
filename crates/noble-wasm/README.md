# Noble Wasm compiler: Calculator-v1 selected source profile

## Compiler change note

The experimental Calculator-v1 source compiler groups adjacent operations into one code-table entry **only when the preceding operation cannot schedule a child**. A call, quotation invocation, match, iteration, or host-effect boundary returns to the dispatcher before the next source operation. The grouped entry executes the same operation actions in order, invokes a runtime tick for **each** action, and stops immediately on failure. Existing `Program` cells retain their original absolute table indices; subsequent commits append entries rather than rewriting old callbacks. The ordinary and declared profiles still allocate one entry per operation and use the unchanged ordinary runtime stack code.

Selected structural signature IDs remain ordered, canonical identities. To keep long-lived sessions inside the existing pool bound, the compiler stores keys in independent blocks of 32: each key stores a common-prefix length, full length, collision-filter fingerprint, and exact suffix (16 bytes of record accounting plus suffix bytes). A fingerprint is **never** accepted as equality: candidate IDs are shared only after decoding and comparing all canonical bytes. Selected emitted WAT still contains the *full* canonical signatures for reflection and retained programs. Literal operation input/output IDs are omitted only where the selected runtime never records that atom's interface; invocation and root/child `Program` interfaces are retained. Ordinary interning and ID order do not change.

The bounds have not been raised: 16,384 imported table slots, 4,096 selected signature identities, at most 65,536 canonical bytes per selected key, and 1,048,576 bytes of **stored** selected signature records and suffixes. Decoded keys are bounded before expansion, and selected WAT remains limited to 4 MiB. Encoding, comparisons, prefix reconstruction, canonical expansion, hashing and output copying charge the existing source preparation Work budget; the selected compiler's cumulative ceiling remains 2,000,000,000. An over-budget preparation fails closed rather than evicting an old `Program` or aliasing a signature. None of these limits or encoding rules changes the ordinary profile.

## Focused observations and limits

- `calculator_retains_sixty_four_long_source_programs_in_one_code_table` passes: a quotation is carried through 64 committed 128-pair `1 drop` source programs, and the final submission still types its invocation as `I64`. A selected V8 run of all 66 submissions returned `42` from that original quotation; each long body reported 513 execution steps and an eight-byte continuation peak.
- A selected V8 boundary probe of the same long body exhausted at step cap 512 with submit-phase execution-work quota reason 6, and succeeded at cap 513. True/false branches after 64 such pairs returned `11`/`22`. The ordinary-profile long-body probe succeeded under its own unchanged caps with 516 steps and the same eight-byte continuation peak; its differently lowered profile is **not** an immutable pre-change Calculator-v1 comparator.
- A local source-bound selected V8 path parsed `12.34`, reduced to exact `617/50`, and emitted actual default ASCII guest Text `617/50` with the original source span. This is a backend smoke observation, not a full calculator acceptance receipt.
- The scoped calculator compiler tests cover hostile generic payload identity, cumulative signature Work exhaustion, oversized derived environments, and retention. No verified immutable pre-group selected compiler build was available, so old-versus-new selected step or continuation-peak *equality* is unobserved. A pair of full function-definition submissions retaining first `State` is likewise not established by the backend smoke probes; do not replace its first failing Work guard with a cap increase or an unmetered copy.
